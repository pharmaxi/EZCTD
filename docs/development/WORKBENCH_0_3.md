# EZCTD 0.3 开发与试用说明

日期：2026-09-07。基点：`f815ab1fbffb66c7e114ffcb6468b230de81cc83`。
当前目的：临床 CRO 直接使用实际持有的模块 5、2.5、2.7 PDF。完整 eCTD 组装不介入当前流程。

## 已实现的这一条路径

本地选择输入目录和独立工作目录 → 启动仅监听 127.0.0.1 的工作台 → 阅读 PDF、翻页、缩放、全文检索、书签跳转 → 明确上下文 → 批量扫描 → 可选导入原报告 → 勾选文件生成快速 Web 查看计划 → 明确确认 → 在独立副本上转换、复验、发布。

本界面不是一个托管网站。PDF 不通过本软件上传到远程服务；HTTP 仅发生在本机浏览器与本机 Python 进程之间。原生解析进程尚不是操作系统安全沙箱；其他本机恶意程序和不可信浏览器扩展不在保护承诺内。

## 安装与运行

从当前 CRO 工程分支开始，检查并保留未提交改动。不要从早期 main 重建代码，也不要强制切分支。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest -q tests/cro_pdf
.\.venv\Scripts\python.exe -m ezctd.workbench
```

最后一条命令用系统目录选择器选择输入和工作目录，随后打开本机浏览器。没有图形目录选择器时用明确路径：

```powershell
python -m ezctd.workbench --root "D:\EZCTD-test\input" --workspace "D:\EZCTD-test\work"
```

输入和工作目录必须是分离的目录，不能相互包含。项目保留终端用于显示错误；关闭终端或 Ctrl+C 停止服务。浏览器关闭不会自动关闭服务。会话地址包含临时访问凭证，不应分享；刷新页面丢失凭证时，从终端完整地址重新打开。

此阶段仅对合成或可丢弃副本试用。Windows 10/11、NAS、真实签章文件及公司终端策略仍需本地验收。不是安装版或生产放行版本。

## 阅读与报告

- 左侧点击文件名阅读；复选框仅用于批量操作范围。
- 物理页码与页面标签分别显示，全文搜索只查可提取文本，不做 OCR。
- 缩放改变显示比例；DPI 改变渲染清晰度，两者不同。
- 文字页可选择与复制提取文本；画布不是原生可选文字层。
- 书签只跳转明确的文内页目标，不自动执行远程链接、JavaScript 或 Launch。
- 修改上下文会清除该文件旧扫描并作废未执行计划。上下文不靠目录名自动确认为豁免。
- 6 章报告导入保持原始字节（含 BOM），只做数据解析。按完整相对路径建立候选，不按文件名猜测。导入不是历史 PDF 身份核验，也不是当前 PDF 已通过。
- 未提供目标与坏链接不同；普通电子申报、eCTD 和用户报告各自保留来源边界。

## 首项副本操作：快速 Web 查看

仅线性化，不做字体替换、附件删除、链接删除、页面重排、OCR 或内容重排。

计划阶段：冻结 SHA-256 → 严格解析 → 检查密码/权限/签名信号/交互表单/组合文档/动态内容/附件 → 列出可执行、阻断、无需重复处理和错误。签名检查包括对象字典及可能的历史 ByteRange 字节信号，不是密码学验证；保守检测可能误阻断，需要单独复核，不提供绕过开关。

执行阶段：再次核对冻结身份 → 内存中重写 → 输出严格结构检查和线性化检查 → 对比可达语义对象图及流 → 每页几何、标签、提取文本和 150 DPI 渲染像素比较 → 源文件再次核对 → 临时输出通过后原子不覆盖发布 → 写每份副本证据。

可达对象图比对保留目录、元数据、书签、链接、标签、资源、流等；排除交叉引用位置、文件 ID 和可逆压缩细节。这不是字节相同，不是所有 PDF 阅读器显示等价，也不是 PDF/A 完整验证。150 DPI 全页像素相同只证明该引擎和参数下的图像比较。

任何复验未完成、不匹配、超时或取消，都不发布成功副本。单个文件失败不阻止后续文件。证据发布失败时只回滚本次创建、身份仍匹配的副本，不删除已有文件。

输出保持原相对路径，置于 `workspace/copies/<run_id>/`，每份 PDF 对应一个 `.pdf.ezctd.json`；`workspace/jobs/` 记录任务结果。**这只是成功处理文件的集合，不是完整交付资料包。** 已经线性化或被阻断的文件不会暗中补拷贝。需要哪些文件组成交付集仍由使用者决定。

本操作是明确选择的通用 PDF 优化，不因旧报告有 6.22 就自动认定当前文件必须修改，也不把优化成功写成官方合规。

## CLI 单文件接口

```powershell
python -m ezctd inspect-copy "D:\test\input\report.pdf"
python -m ezctd linearize-copy "D:\test\input\report.pdf" --output "D:\test\out\report.pdf" --expected-sha256 "从上一命令读取的真实SHA256" --approve
```

没有批准、身份变化、目标已有文件或位于输入目录中，都拒绝写入。

# EZCTD 0.4 页面组织、阅读与批次工作台

本分支版本：`0.4.0.dev0`。本轮在长临床报告阅读、检查和混合批次基础上，增加真实页面重排与持久旋转；安装入口、仅本机 HTTP、输入目录与工作目录分离的要求与现有工作台一致。

## 安装与启动

在本任务分支的源码目录中执行，使用 Python 3.12 或 3.13：

```powershell
python -m pip install -e ".[test]"
python -m pytest -q tests/cro_pdf
python -m ezctd.workbench
```

没有系统目录选择器时明确指定两个互不包含的目录：

```powershell
python -m ezctd.workbench --root "D:\EZCTD-test\input" --workspace "D:\EZCTD-test\work"
```

从终端给出的完整会话地址打开浏览器。页面凭证仅保存在当前标签页内存中；需要重新打开页面时使用同一服务的完整地址。关闭浏览器不会停止后台任务；终端 Ctrl+C 才会停止服务。服务重启后须重新扫描或规划，旧任务 JSON 不能恢复写入权限。

## 阅读、定位和检查

1. 左侧点击文件名阅读，复选框决定批量操作范围。文件路径和扫描状态可以同时筛选；“选择全部”只影响当前可见列表。筛选外仍选中的数量会单独提示，生成计划前核对选择范围。
2. 阅读区显示物理页码、PDF 页标签、真实渲染 DPI。显示缩放与渲染 DPI 分开控制。超大页按像素预算完整缩小，界面会说明已降低清晰度；这不改变源 PDF，也不降低副本复验的门槛。
3. 在“导航”中显示缩略图，每次至多加载 12 页、并发至多 2 个；可以继续加载下一组。书签筛选保留命中项的祖先，不执行外部目标或动作。
4. 输入检索词后按 Enter 检索当前页，Shift+Enter 检索全文。全文每批最多 200 页；点击“继续检索”遍历后续页。结果片段围绕命中显示，页标签与物理页同时保留。
5. “已遍历文本层”只描述可提取文本的覆盖。无文本页没有做 OCR；读取未完成页、每页命中上限和未检索后续页分别列出。改变查询时旧高亮和结果会清除，迟到响应不能显示为新查询结果。
6. 右侧完整保留 26 条规则状态，可筛选明确问题、未判定、未运行等。对象证据与页定位保留在结果内；原报告观察在独立页签中，路径候选不代表历史 PDF 身份相同。

“专注阅读”收起侧栏；退出后继续选择和检查。Ctrl/Cmd+F 聚焦检索框，Alt+左右方向键翻页。提取文字可在“文本”页签复制；页面画布尚不是原生可选文字层。

## 组织页面、保存与重新打开

1. 点击文件名后进入 **组织页面**。页面网格的编号表示当前输出页位，来源页号表示原文件中那一页；PDF 页标签另行显示。
2. 点击页面选择，Shift 连选，或用范围框输入 `2-3,5` 选择当前页位。移动时所选页保持彼此顺序，作为一组放到指定起始页位；可以前移、后移或拖动。
3. **顺时针/逆时针旋转**每次改变 90°。预览由真实修改后的 PDF 渲染，保存时也会写入页面方向。已有旋转与本次增量叠加，不会把所有页面都强制归零。
4. **撤销/重做**针对 PDF 编辑；**还原**恢复原始顺序和方向。切换文件不会删除草稿，保存后仍可使用历史。当前每个工作区最多 16 份编辑草稿，每份保留 50 步历史；关闭服务后不恢复草稿。
5. 核对页面预览及来源映射后点击 **保存副本**。后台冻结本次修订，完成逐页显示、文本、页树、导航和非目标结构复验；保存期间不能继续编辑该草稿。
6. 完成后点击 **打开已保存副本**，或切到 **已保存副本**。这里读取实际输出，并重新核对其 SHA。可翻页、查看文本和书签目标；返回草稿继续编辑会生成新的修订。

每份输出与 `.ezctd.json` 证明保存在独立工作目录 `copies/<任务ID>/<原相对路径>`。输入文件和已有输出均不覆盖。相同修订的重复保存请求会返回原任务，避免断线后重复生成；失败或取消后可在编辑区明确重试，新任务使用新目录。页面组织的重试不会转成线性化计划。

页面组织当前处理 1–2000 页、200 MiB 以内的单文档完整页集。普通内部书签、链接、命名目的地和已有页标签应保持其内容目标；原件未设置页标签时不生成标签。签名信号、加密、表单、附件、动态内容及当前未支持的结构/目标形式会明确阻断，原件仍可使用已有阅读入口。数字签名信号不等于密码学签名验证。

源文件在会话中变化会使草稿失效。已保存结果如被外部改动，也不能继续显示为已复验版本。草稿导航的页位映射与保存后从实际 PDF 读取的导航分别标识；原件扫描和原报告不会被展示为编辑后重新检查的结果。

## 批次、计划与恢复

“扫描选中”只检查勾选文件，“扫描全部”检查工作区全部 PDF。两者均保留原文件。扫描完成后左侧状态更新，但未决状态不能当作官方通过。

“生成修改计划”逐份检查快速 Web 查看副本的适用性。正常、损坏、签名和已线性化文件可以放在同一批；损坏文件保留错误，签名等信号阻断重写，已线性化文件无需处理。仅身份已核实的合格子集可以明确确认执行。确认框逐行说明哪些文件将处理；来源或上下文变化会使对应计划失效。

生成副本时继续使用既有事务：重新核对源身份与限制 → 临时候选 → 结构、每页提取文本和 150 DPI 全页像素比较 → 复核来源 → 禁止覆盖发布 PDF 与证明。所有成功副本位于独立工作目录，保留相对路径。它们只是成功处理文件的集合，不是完整交付资料包。

“任务历史”显示当前服务会话的任务、逐文件结果和关联重试。成功、错误、取消、未开始、阻断、无需处理分别统计。重试规则如下：

| 原任务 | 重试内容 | 新任务 |
| --- | --- | --- |
| 扫描 | 错误、取消、未开始项 | 新扫描 |
| 计划 | 错误、取消、未开始项 | 新计划 |
| 副本生成 | 错误、取消、未开始项 | 新计划，仍需再次确认生成副本 |

已成功文件不会因重试而再次生成。已取消计划中的已完成预检行也不能执行；若要处理这些文件，重新选择并生成新计划。

请求中断时，后台可能已接受任务。“重新连接”会读取实际任务历史并恢复进度，不自动重复提交修改。即使任务响应丢失后后台已完成，也能从历史查看结果；如果服务器确实没有任务，操作按钮恢复可用。

若源文件在会话中变化，旧页面、缓存、扫描和可执行计划会失效。重新打开工作区确认新版本；不要把新文件替换到旧会话后继续沿用原计划。修改资料上下文同样需要重新检查和规划。

## 给另一位开发者的实际试用

使用合成或可丢弃 PDF。仓库浏览器脚本会建立全新的合成目录并保存原件哈希、任务证据及截图：

```powershell
python -m pip install -e ".[test,ui-test]"
python -m playwright install chromium
python tools/review/test_workbench_browser.py build/trial-0-4
```

该目录必须尚不存在；不要覆盖此前证据。自动脚本完成后，在独立的工作目录中人工打开 `build/trial-0-4/input`，按下面顺序试用：

1. 阅读临床报告，翻页、数值检索、书签、缩略图、专注模式和退出；调整窗口宽度检查工具条与按钮可达。
2. 勾选两份文件，改变筛选条件，确认筛选外选择提示；执行“扫描选中”，再用规则状态筛选检查证据与页定位。
3. 勾选正常、损坏、签名和无需处理文件生成混合计划；逐行核对可执行集合，确认后核对成功副本及 `.ezctd.json`，比较全部输入 SHA-256。
4. 从历史打开已用计划，确认不能再次执行；仅重试损坏文件并核对 `retry_of` 与新任务范围。
5. 在单独的可丢弃会话中规划后修改一份源件，重新读取触发身份检测；原计划该行应显示失效。此步骤故意改变测试输入，不能与“原件未改”的主流程证据混记。
6. 若有超过 200 页的合成报告，检索命中第 201 页的词，继续后一批并核对实际页号。浏览器脚本包含该原生样例和嵌套书签检查。
7. 用 `build/trial-0-4/page-organizer/input` 启动新的独立工作区。打开 6 页报告，选择第 2–3 页并移到第 5 页位，顺时针旋转；撤销两次、重做两次，再保存副本。重新打开后的来源页序应为 `1,4,5,6,2,3`，标签为 `i,2,3,4,ii,1`，最后两页方向为 180°、90°（来源第 2 页原已有 90°）。点击嵌套书签应到输出第 4 页、内容仍为来源第 6 页；输入哈希应保持不变。

只迭代页面组织时可以运行同一组真实浏览器案例：

```powershell
python tools/review/test_organizer_browser.py build/trial-organizer
```

完整 CI 仍从既有 `test_workbench_browser.py` 进入，同时运行原阅读/批次流程与页面组织案例。证据目录必须为新目录。

实际运行结果见 [验收记录](../specs/pdfcraft-workbench/tasks.md)。独立 AI 审查和自动测试不替代另一位开发者试用；按照 `AGENTS.md`，当前提交 CI 通过、对方审核及明确合并指令齐备后才能合并。

## 本次验证的限度

尚未进行公司 Windows 10/11 与 NAS 环境验收、真实临床签章业务验收、密码学签名验证或 CDE 官方等价校准。默认没有 OCR、字体替换、有损压缩、目的地删除或完整 Publisher。纸质签章扫描件的业务处理口径沿用现有待确认状态。

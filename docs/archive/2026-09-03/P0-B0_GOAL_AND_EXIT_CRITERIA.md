# P0-B0 目标与退出条件：26条PDF规则验证矩阵

> 状态：`P0-B0a specification ready / official black-box pending`  
> 目标规则包：`cn-cde-ectd-v3.2.2-v1.1-pdf`  
> 官方验证器目标：CDE eCTD验证软件 V1.1.0  
> 基准日期：2026-09-03

## 唯一目标

为 CDE《eCTD验证标准V1.1》第6章 6.1–6.26 建立能够直接驱动开发和验证的五联证据：

```text
正式来源 → 检测合同 → 最小变异样本 → 官方验证器预期/实测 → 未决问题及处置
```

不是“把26条抄进JSON”，而是把每条规则变成可重复实验。

## 总体退出条件

P0-B0 只有在以下条件全部满足时才能标记完成：

1. 26/26 规则均回溯到正式生效的 CDE 原文，并登记页码、严重程度和豁免。
2. 26/26 规则均定义机器可读 detector contract，包括所需上下文和输出粒度。
3. 每条规则至少4个样本，整体至少104个；实际当前规范为 **163个**。
4. 每条规则至少具有合规、违规、边界或豁免中的三类；规则交互必须单独标注。
5. 所有样本生成过程可重复，输入和输出均记录 SHA-256。
6. 使用 CDE eCTD验证软件 V1.1.0 对全部目标样本实际运行，并保存：安装包哈希、软件版本、OS、原始报告、截图或日志、运行时间和样本哈希。
7. `expected_cde` 与 `observed_cde` 分开保存；未经运行不得填“已确认”。
8. 官方验证器与EZCTD不一致的每一项均有差异分类：规则理解、样本构造、上下文、官方软件行为或EZCTD缺陷。
9. 规则矩阵和测试清单通过CI结构校验。
10. 形成一次独立复盘，明确哪些规则可以进入P0-B只读扫描器，哪些仍应阻断。

## 本分支可完成的阶段：P0-B0a

本轮完成：

- 26条 detector contract；
- 163个测试案例规范；
- 首批可执行 PDF fixture 生成器；
- 官方验证器黑盒协议和观察结果数据格式；
- 来源台账与当前缺口；
- 矩阵CI校验；
- 第一次阶段复盘。

本轮不能虚假宣称完成：

- 尚未取得并运行官方验证软件 V1.1.0；
- 尚未解包固化《eCTD技术规范V1.1及附件包》；
- 尚未形成一个可被官方验证器接受的最小完整 eCTD 序列骨架；
- 官方输出中的规则编号、去重、优先级和计数行为尚未实测。

## 进入P0-B只读Scanner的门槛

规则可以进入实现队列，至少要满足：

- 原文已核验；
- detector合同完整；
- 有一正一反最小样本；
- 本地oracle能够定位到文件/页/对象；
- 与其他规则的交互已知或显式保留为多finding；
- 不依赖尚未取得的节点上下文时，可先实现文件级检查；
- 依赖eCTD节点的规则必须等目录映射和最小序列骨架完成。

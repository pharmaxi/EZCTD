# P0-B0 Review 001：从规则抄录转向可证伪实验

## 复盘结论

此前P0-A把26条规则逐条回源是必要步骤，但“source verification complete”容易被误读成实现依据已经充分。实际仍缺三类关键证据：技术规范RAR、节点映射XLSX、官方验证器V1.1.0字节与行为。

本轮采取的修正：

- 不删除P0-A成果，但把后续状态明确为`P0-B0a specification ready / black-box pending`；
- 建立163个案例，而不是只写26个自然语言检测建议；
- 强制区分`expected_cde`和`observed_cde`；
- 对规则交互单独建模，禁止把官方可能的抑制逻辑提前写死；
- 建立可生成的最小PDF变异样本及manifest；
- 把所有豁免视为eCTD上下文规则，而不是文件名规则。

## 本轮发现的高风险误判点

1. **6.18与电子签章**：Signature Widget属于注释体系，但实施指南又要求特定文件签章。必须由官方软件实测特殊处理。
2. **6.8/6.15的zoom=0**：PDF语义上0可等价于保留缩放，但官方验证器可能只接受null。
3. **6.16的PDF/A**：只看Header或XMP会把伪PDF/A误判为合规，真实一致性需独立验证。
4. **6.19/6.21**：打开密码与权限限制是两个不同问题；加密但可直接打开仍可能触发6.19。
5. **6.23**：‘有书签’可能只看Outlines非空，也可能要求书签有效；会与6.5/6.6联动。
6. **路径规则**：绝对路径、file URI、包外相对路径同时落在6.2/6.3或6.9/6.10边界。

## 反证检查

- 没有把ICH 500MB覆盖到中国200MB区域规则。
- 没有把商业软件行为写入官方规则。
- 没有声称已经运行CDE验证器。
- 没有把PDF修复策略混入官方规则原文。
- 没有把参考文献豁免扩展到所有规则；6.1、6.21无同类豁免。

## 当前是否可进入扫描器开发

可以开始实现低争议的只读对象采集层，但不应立即冻结finding语义。优先实现：

- PDF可读性和页数采集；
- outline/action/destination规范化；
- Link注释/action规范化；
- version、encryption、attachments、annotations、PageMode/PageLayout、linearization、字体和逐页文本统计；
- eCTD节点上下文接口。

暂缓冻结：6.18签章、6.8/6.15 zoom=0、6.16 PDF/A、6.19/6.21边界、6.25阈值、6.26标准字体名单。

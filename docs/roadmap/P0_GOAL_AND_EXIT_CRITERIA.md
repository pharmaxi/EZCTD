# EZCTD P0 目标与退出标准

> 基准日期：2026-09-03  
> 工作分支：`agent/p0-b0-validation-matrix`  
> 状态：执行中  
> 官方 CDE V1.1.0 黑盒观察：`0 / NOT_RUN`

## 1. 唯一目标

P0 的目标不是发布 PDF 修复器，也不是生成可递交的 eCTD 序列，而是建立一个**可审计、只读、证据驱动的中国 CDE eCTD PDF 预检基线**：

1. 26 条 PDF 规则均能追溯至当前有效的 CDE 正式来源；
2. 官方原文、工程解释、检测算法和修复设想彼此分层；
3. 每条规则均有机器可执行的阳性、阴性、边界、豁免或交互实验；
4. 只读观察器能够输出文件、页码、PDF 对象和检测证据；
5. 观察器不得修改输入文件的任何字节；
6. 包级检查器能够验证路径、XML 引用、MD5、节点上下文和 PDF 叶文件；
7. CDE eCTD 验证软件 V1.1.0 的真实结果能够被完整、可复核地采集；
8. 所有不一致均保留为实验结果，不通过修改规则标签来制造“全绿”。

## 2. 明确非目标

P0 不包括：

- 自动修复或覆盖任何 PDF；
- 生成生产级中国 eCTD 申报序列；
- 实现 `new/replace/append/delete` 生命周期；
- 自研电子签章；
- 自动嵌入缺失字体；
- 自动删除所有外部链接、注释或未知对象；
- 宣称取代 CDE 官方验证软件；
- 在没有官方运行证据时宣称灵敏度、特异度或等价性。

## 3. 分阶段门槛

### P0-A：监管证据包

退出条件：

- [x] 固定 CDE eCTD V3.2.2 / 中国技术文件 V1.1 的生效基线；
- [x] 固定 PDF 规则 6.1–6.26 的标题、严重程度、解释和公开例外；
- [x] 规则数与严重程度总数通过机器校验；
- [ ] 官方技术规范、附件、实施指南、验证标准、目录对应表、验证软件和手册的原始二进制均完成官方来源哈希固化；
- [ ] 官方技术包中的 DTD/XSD/XSL、区域 XML 和目录映射完成静态解析。

### P0-B0：实验语料与探针

退出条件：

- [x] 26 条 detector contract；
- [x] 130 个 case recipe；
- [x] 28 个 smoke fixture 定义；
- [x] 单规则阳性与规则相关性/不可隔离性分开表示；
- [x] object、PDFium、qpdf、可重复性和差分资料包探针已实现；
- [ ] 最新收敛 workflow 对全部本地门槛给出机器 PASS，并固化提交 SHA；
- [ ] 对所有失败样本保留日志和最小复现文件。

### P0-B1：只读预检内核

退出条件：

- [x] 26 条规则的实验性只读观察器已实现；
- [x] 节点、资料类型和语言上下文契约已实现；
- [x] 候选 eCTD 包级路径、XML 引用、MD5 和 PDF 叶检查已实现；
- [x] 输入前后 SHA-256 完整性检查已写入门槛；
- [ ] 最新收敛 workflow 证明 26/26 目标条件命中、baseline 0 finding、28/28 文件字节不变；
- [ ] 至少三类非合成、脱敏 PDF 语料完成只读扫描和人工复核。

### P0-B2：官方软件校准批次 01

退出条件：

- [ ] CDE eCTD 验证软件 V1.1.0 安装包来源、SHA-256、数字签名和版本资源已固化；
- [ ] 操作手册已固化；
- [ ] 一个中国 eCTD baseline sequence 经同一版本软件验证无第 6 章阻断；
- [ ] 按固定顺序完成 9 次运行：3 次 baseline 控制 + 6 个目标阳性；
- [ ] 每次运行均保存原始报告、全屏截图、输入 inventory、时间和复核记录；
- [ ] 明确 6.19/6.21 共存关系、6.8 缩放语义、6.22 线性化判据和 6.26 字体判据。

### P0-B3：26 条官方黑盒矩阵

退出条件：

- [ ] 26 条目标规则均至少有 1 个 CDE V1.1.0 阳性观察；
- [ ] 每条规则至少有阴性或豁免对照；
- [ ] 130 个边界/交互实验完成优先级分批运行；
- [ ] 结果分为 `MATCH / PARTIAL / OFFICIAL_ONLY / EZCTD_ONLY / INCONCLUSIVE`；
- [ ] 所有差异均可追溯到原始报告和输入哈希；
- [ ] 形成 detector 版本冻结候选，而不是修复器。

## 4. P0 的最终退出判据

P0 只有在以下条件同时满足时才能结束：

```text
监管来源完整
AND 本地合成门槛通过
AND 只读完整性通过
AND 官方校准批次通过
AND 26 条官方黑盒覆盖完成
AND 所有关键差异已有处置结论
```

任何一个条件缺失，都不得把 P0 标记为 `Complete`。

## 5. 当前最硬目标

当前硬目标固定为：

> **取得并固化 CDE eCTD 验证软件 V1.1.0 与操作手册，建立一个经该软件验证干净的最小中国 eCTD baseline sequence，随后完成校准批次 01 的 9 次运行。**

在此之前可以继续完善本地观察器和证据合同，但不能用新增代码替代官方观察。

## 6. 决策原则

1. 正式生效的 CDE/NMPA 文件优先于行业文章和商业软件行为；
2. ICH 规范提供国际骨架，中国区域文件控制中国区域实现；
3. GitHub 项目只提供实现参考，不提供监管权威性；
4. 不可自动获取的官方二进制可以人工下载，但必须经来源、哈希和静态检查导入；
5. 任何自动化通过标记都必须由实际输出反推生成；
6. 失败证据和未解决项与成功证据同等保留；
7. 自动修复在 P0 结束前保持禁用。

# CRO PDF 当前交付路线

更新：2026-09-07。范围由用户确认：重点处理实际持有的模块 5、2.5、2.7 PDF，不取得、不虚构完整申报包。本文取代旧 P0 最小序列的强制产品前置条件；历史研究结果保持原状。

## 当前已实现的可运行增量

目录递归发现 → 每文件独立进程扫描 → 输入身份复核 → 逐规则完成状态 → 中文 HTML/JSON。当前页面服务支持物理页/标签/页框/旋转、文本提取、原生字符索引搜索定位和有像素上限的 PNG 预览。

安全入口采用拒绝覆盖的输出，输入/依赖树与输出分离；读取范围在访问目标前检查。普通跨文件目标缺失显示未提供，不能直接删除。字体清单遍历继承资源与 Form XObject；CDE 名单和 Base-14 分开；别名、复杂资源及规则穷尽性未确认的仍为 INDETERMINATE。

这不是完整桌面程序，也没有批量修改用户 PDF。真实环境适配、全部规则语义、密码学签名校验和资源沙箱仍未完成。

## 下一交付：基础 PDF 工作台

用户在一个界面内打开临床目录、查看缩略图、翻页/缩放、搜索数字/中文/英文、点击问题定位到页面及对象。页面按需加载，不能为打开一个大图谱预渲染所有页面。默认保留原中文目录，单独确认正式 CTD 节点；空腹/餐后同名附件通过相对路径与文件身份区分。

验收：真实渲染而非占位图；物理页、标签与正文编号分开；CropBox/Rotate 坐标变换可验证；未找到旧报告文件显示未绑定；已改变文件使绑定和修改计划失效。首个 UI 应共用当前核心服务，不复制规则逻辑。

## 随后交付：首个批量副本操作

优先候选：对明确适用、未签名、未加密且可解析的 PDF 启用快速 Web 查看。其他初始视图/承前缩放可逐项加入。每一项操作必须有独立守卫、前置计划、非目标属性检查和输出验证。

验收：不覆盖原件/既有输出；全部输入前后哈希；独立输出路径；失败隔离；输出重开、目标属性、页数、文本、导航和全页同参数渲染比较；签名信号阻断；记录实际修改，不能把保存成功当修复成功。不要求其余 25 条都校准后才能开发一项，但该项不得省略自身验证。

尚未提供实现的操作：合并/拆分/重排/旋转保存、书签/链接编辑、页面标签和页码叠加、附件提取移除。它们在产品规格内，不是本次完成项。字体补嵌优先支持精确资源可确认场景，其余形成回源任务；不得统一替换字体或把全部页面转图片。

## 并行官方对照

以合成的部分临床文件夹做处理前后对照，保留完整原报告，重点比较第 6 章。缺骨架的非目标消息单独显示，不改成通过、不计入 CRO PDF 整理失败。规则适用性必须结合实际资料角色，不直接靠文件名猜测。

用户提供的历史 HTML 是外部观察，不增加 Agent 自行运行计数，也不是控制—处理校准。旧报告无 PDF 哈希时，不能证明当前版本一致。

## 持续限制与退出条件

当前目录扫描的 200 MiB/文件、10000 PDF/目录、页面预览 1600 万像素、60 秒默认超时是工程限制，不是新的法规要求。原生依赖在单独进程中运行，但并无完整 OS 内存/网络沙箱。Windows/NAS 的恶意并发替换、重解析点和大文件压力测试应在产品化前完成。

完成一个阶段的证据是：固定提交、测试报告、演示输入与输出、明确未完成项。不是提交次数、规则 JSON 行数或“所有步骤成功”的截图。

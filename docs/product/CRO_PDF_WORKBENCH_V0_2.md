# EZCTD v0.2：临床 CRO 的 PDF 工作台与第 6 章批量处理

> 决策日期：2026-09-07。需求方明确：临床 CRO 通常只能获得部分申报资料，重点是模块 5、2.5、2.7。本文在产品范围与开发顺序上取代此前“先建立完整最小 eCTD 序列”的前置要求；不改写历史实验、正式规则和既有验证结果。

## 1. 产品目标

将 EZCTD 定义为本地 PDF 工作台，而不是完整申报 Publisher，也不是只会汇总错误的报告工具。

用户应能在没有 index.xml、cn-regional.xml、申请编号和模块 1/3/4 的情况下，导入临床文件夹，阅读/检索/组织 PDF，解析书签、链接、字体、页面与签名，对第 6 章问题执行受控批量修改，复验后交付 PDF 副本与变更清单。完整申报资料由拥有全部资料的一方负责组装与最终验证。

普通 PDF 模式和 CRO 临床资料模式均须可用。报告是可选证据输入；没有官方报告也要能独立扫描 PDF，不能把“导入 HTML”当作“PDF 解析完成”。

### 核心范围

- 模块 5：临床报告、附件、统计/生物分析报告、方法学验证、图谱、CRF、个例列表和参考文献。
- 2.5：临床综述；2.7：用户提供的临床总结各部分。
- 可附加 CRO 实际提供的模块 1 证明材料，但不要求提供完整模块 1。
- 第 6 章 6.1—6.26 是当前重点处理目录，不因本例只有四种问题而删除其他检测能力。
- 保留用户中文目录。5.3.1.2 下的空腹/餐后文件夹是项目组织维度，不自动当成新的正式 CTD 节点。

### 不再作为开发前置条件

完整 0000 序列、全部申报元数据、所有模块、前五章零错误、完整 DTD/XSD 生成、生命周期或 STF 全部合格。官方校准改用实际 CRO 部分资料模式与合成 PDF 正反对照；确实需要完整上下文的实验另行标注。

### 两类必须保留的矛盾

1. 原文对参考文献存在豁免，而 5.4 参考文献被列为附件问题；6.22 与 6.26 也包含参考文献命名的路径。可能涉及无 XML 时节点识别、实际文件角色或软件行为；目前不能选一个解释当事实。
2. 字体原始名单中有 Times-Roman、Helvetica，也有 Times New Roman、Arial 的变体以及乱码。不能把 Base-14 等同于 CDE 名单，不能按逗号机械切分字体名，更不能把这些字体一律替换为宋体。

保留原报告发现 + 单独适用性复核 + 本地 PDF 当前观察，不能删除原报告记录制造一致。

### 输出污染实例

报告 2.4 显示一个旧 HTML 验证报告位于输入临床目录的 output 子目录。即使聚焦第 6 章，也应提示这种交付污染：修复输出、报告、缓存和附件提取结果须与输入/待交付 PDF 文件树分离。

## 3. 基础 PDF 软件能力，不是后置装饰

| 能力层 | 首批必须具备 | 限制与验收 |
|---|---|---|
| 阅读 | 打开、缩略图、分页、缩放、旋转查看、多文档切换、目录和书签导航 | PDF 物理页码、页面标签、正文页码分开；大图谱按页按需渲染 |
| 检索 | 文本选择复制、中文/英文/数字/单位搜索、命中定位 | 无文本层与提取失败分开；无法正确映射文字时不得声称可搜索性正常 |
| 页面组织 | 提取、拆分、合并、插入、删除、重排、持久旋转 | 独立副本；维护页映射；检查失效书签、链接、页码、表单；签名文件不直接重写 |
| 书签/链接 | 查看和编辑树、导入导出、批量缩放、目标页/目标文件选择、矩形高亮、创建修正删除 | 不自动猜语义目标；删除只针对确认的对象，不删除所有导航 |
| 属性 | 版本、元数据、初始视图、权限、附件、字体、图像、页面框、表单、数字签名清单 | 原始对象证据与法规判定分开 |
| 批量优化 | 初始视图、承前缩放、线性化、无损结构整理、保存预设 | 不一律转换 PDF 1.7；不默认栅格化、转灰度或降低图谱清晰度 |
| 辅助制作 | 页面标签、页码/页眉页脚、目录链接辅助、按页 OCR、指定注释处理 | 需预览，防遮盖；不以打印成 PDF 的方式统一扁平化所有 CRF |

首版不承诺 Acrobat 式任意内容重排，但必须能看、找、定位、组织、编辑导航和保存副本。通用文本内容改写、通用字体补嵌和无审核自动目录识别不进入默认批处理。

## 4. PDF 解析能力合同

解析器至少提供：页面树、MediaBox/CropBox/Rotate/UserUnit、文本及字符位置、字体及实际使用页、图像和 Form XObject、书签树、命名目的地、链接与动作链、附件、注释/表单、签名字段及 ByteRange、元数据、版本/加密/线性化。

- qpdf/pikepdf 用于对象结构，PDFium 用于独立渲染；不把 qpdf 与 pikepdf 计作两个独立底层。
- 页面资源应遍历继承资源、Form XObject 和嵌套对象；设置循环、深度、资源量与时间上限。
- 提取文本失败不是无文本，首末页可渲染不代表全页完成。
- 引用目标只在用户明确选中的读取范围内打开。已导入目标可校验；范围外但可能由申办方提供的目标标为未提供；不是自动认定失效或直接删除。
- 签名字样/扫描手写签名和密码学签名是不同对象；不能靠文件名判断。
- OCR 文本层增加不改变科学内容，仍需检查数字、小数点、符号、单位、页面视觉与文本可检索性。

## 5. 报告到批处理的真实工作流

导入 PDF 文件夹 → 可选导入原始 HTML → 提取第 6 章 → 以相对路径/文件身份绑定当前文件 → 显示差异与未绑定项 → 当前文件重新扫描 → 确认资料角色与适用性 → 生成操作计划 → 预览并批准 → 输出独立副本 → 本地复验 → 同目录组织方式重新跑官方软件并比较第 6 章。

本报告没有每个输入 PDF 的哈希，所以按路径匹配只代表“候选绑定”，不能证明当前文件就是五月运行的版本。当前扫描哈希与操作时哈希必须一致；任何外部修改使计划失效。

同名附件在空腹/餐后目录中很多，禁止只用 basename 自动配对。报告中的矩形坐标必须根据实际 PDF 的页框、旋转、缩放变换映射后人工确认，不能拿坐标直接执行删除。

### 四种报告高频问题的处理

- 6.22：确认非豁免、未签名、可解析且当前仍未线性化后，批量写入副本；作为最后一轮 PDF 写入步骤；重新检查线性化与页面/导航。
- 6.26：批量盘点真实字体程序和嵌入状态，聚类到来源文件或导出链；精确可嵌入场景才处理。优先回 Word、统计程序或生物分析报告生成器重新导出；不得把改字体名称当修复，不默认栅格化。
- 6.12：重读实际第 2 页，定位对象并检查动作。有效目标可确认时修正；确属无用残留链接时才删除该注释。禁止整页清除注释。
- 6.17：先列附件的名称、类型、大小与哈希，不执行附件；先复核参考文献豁免。需要去除时先安全导出附件并经确认，仅从副本移除，不丢失资料。

## 6. CRO 部分资料模型

项目明确 `dataset_completeness=PARTIAL_CRO`，预设主范围为 5、2.5、2.7。未提供模块不算本软件任务失败，不虚构 XML/申请编号以补齐。完整申报缺项在“交付给申办方的整合提示”中保留，不能改写成官方已通过。

每个文件记录相对路径、稳定文件 ID、当前 SHA-256、CTD 节点候选/确认值、资料类型、语言、研究/分支、责任人、上下文证据来源。路径推断只能生成候选。2.7.5、5.4、外文参考资料逐条规则判断，不是一键豁免所有安全检查。

链接目标状态区分：当前范围内可验证、用户明确提供的只读依赖、未提供/交付方待整合、确认损坏、禁止访问的外部路径。部分交付范围外不等同于整个申报包外。

## 7. 结果可信度与安全入口

### 结果分三份保存

1. 原报告观察：规则编号、原始等级图标、明细数、原文/定位、源 HTML 哈希，不可改写；
2. 当前本地检查：源 PDF 哈希、解析器版本、逐规则状态与证据；
3. 处置结果：修改/保留/豁免待确认/回源/申办方待整合，人工理由与复验结果。

逐规则状态至少为 PASS、FAIL、NOT_APPLICABLE、INDETERMINATE、NOT_RUN。官方报告“通过”只属于当时那次运行。无明细的提示图标不自动生成问题；报告计数与解析明细不一致则导入不完整。

输入保护在所有入口共用：GUI、CLI、批量任务和报告导入。禁止原地覆盖；禁止同文件硬链接/符号链接别名写入；新输出不覆盖已有结果；报告不得落到输入根内；发布前校验临时结果。输入选择范围之外不做自动读写，不执行 PDF 脚本和 HTML 脚本。

任意已有签名的文件默认不可修改。页面删除、重排、合并、内容叠加和附件删除均是有意义的变更，不能仅通过像素相同宣布无损；导航/文本/字段/签名/附件等按操作类型分别复核。

## 8. 当前实施状态（0.2.1.dev0）

本节取代前一轮“仅 24 项报告导入与输出边界单元测试”的实现快照，历史证据仍保留。

已实现：

- `scan-directory`：无需 XML 的目录级批量扫描、显式只读依赖根、每 PDF 独立进程、超时/异常隔离、输入清单前后哈希、中文 HTML 与 JSON。
- `inspect-page` / `render-page`：真实 PDFium 页面几何、页标签、文本、原生字符索引搜索及坐标、限制像素数的 PNG 预览。这是核心服务，不是已完成桌面界面。
- `read_scope.py`：访问前校验允许读取根；不跟随链接组件；未提供的相对目标不自动当损坏；不自动访问绝对路径/UNC/URI。
- `assurance.py`：逐规则保留五种执行状态；仅有限属性检查允许 PASS；复杂语义与上下文缺失仍保留 INDETERMINATE。
- `pdf_resources.py`：继承资源/Form XObject 的使用字体遍历，精确 CDE 名单与原始字体名称、嵌入状态分开；不再使用 Base-14 替代名单。别名确认与完整资源图仍待完善。
- 修正远程命名目的地在目标文档内解析，XYZ 缩放 0 与 null 均作为保留缩放编码。
- 原安全报告导入能力保留；纯报告导入与父进程不预加载原生 PDF 引擎。安全输出支持 UTF-8 文本及 PNG 字节，均不覆盖已有输出。
- 本地 54 项针对性测试通过，包含真实 PDF 引擎和 20 文件混合批次；密码文件和损坏文件均得到明确状态，20 个输入哈希未变。


跨平台复验：代码提交 `95f197c097119fbc2c3620cb24cec442aed26b7f`，Actions run `34090491339`；Linux 与 Windows 各 54 项通过、0 失败、0 跳过。两边使用 pikepdf 10.13.0.post1 / pypdfium2 5.13.0，原始 JUnit、依赖清单与源码归档已下载核对。Windows 源码归档为 CRLF，规范化行尾后与本地源码一致；不把原始字节哈希写成相同。这不等于 Windows 10/11、NAS 或未知恶意 PDF 的产品级验证。

尚未完成：桌面界面、实际 PDF 批量修改、完整报告绑定、密码学签名验证、OCR、全部导航/资源边界、大型真实文档压力测试和 Windows/NAS 产品环境验收。不要把候选字体发现当作精确字体修复结果，不把首末页诊断渲染当全页验证。

工程上限与信任假设详见 `docs/roadmap/CRO_DELIVERY.md`。未来副本操作必须另行通过该操作的签名守卫、文本/导航/结构和全页渲染复验，不能用本次只读测试替代。

## 9. 开发顺序与验收

A. 安全/可信度：在真实引擎上补齐读取边界和逐规则状态；同路径别名、全输入清单、异常和崩溃不误写。所有旧安全发现逐项关闭。

B. 基础 PDF 工作台：能打开、检索、翻页、定位对象，提取/拆合/重排副本；中文路径和图谱可用。报告导入与原 PDF 重新扫描相互独立。

C. 首个批量处理纵向切片：非豁免未签名文件的初始视图/承前缩放/线性化副本处理，带操作预设、逐文件取消/失败隔离、结构与视觉复验。不得以 320 条直接等于 320 次安全自动修复。

D. 难点功能：字体精确处理与回源流程、附件清单/提取、失效链接修复、OCR 和批量书签辅助。原 PDF 暂未提供时先用合成样本开发，不要求取得全套申报资料。

E. 官方对照：使用不完整临床文件夹执行处理前/后对照，固定范围、原 PDF 哈希、软件版本/配置，重点比较第 6 章；保留非目标消息，不为修复第一至五章扩展产品范围。

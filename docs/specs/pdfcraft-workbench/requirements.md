## 明确范围

本次不增加 PDFCraft/Rust 依赖，不引入付费 API、云上传或外部字体。第一阶段沿用线性化副本；第二阶段新增单文档完整页序的重排与持久旋转。默认不删命名目的地、附件或字体，不做 OCR、通用内容编辑或有损压缩。PDFCraft 自检和本地自动测试均不代表官方规则等价、申报合格或 Windows/NAS 产品验收。任务历史和编辑草稿限当前服务会话，不从旧 JSON 静默恢复可执行计划。

## 第二阶段：页面组织与真实 PDF 修改

用户于 2026-10-10 明确，深度参考 PDFCraft 的重点是工作台与 PDF 处理能力。这与原产品规格 §3、§9 一致。第一条可交付流程是：打开 PDF → 多选页面 → 重排及持久旋转 → 查看实际编辑结果 → 撤销/重做 → 保存副本 → 重新打开并核对页序、方向及导航。

| ID | 可观察行为 | 验收 |
| --- | --- | --- |
| E1 | 原件阅读、页面草稿、已保存副本有明确身份；同一文件切换回来保留草稿 | 原件页面和扫描证据不会被误当作修改后结果；切换文件与异步晚到不串页 |
| E2 | 页面可多选、按范围选择、移动到指定位置；提供拖动及按钮/键盘替代 | 输出完整包含每个来源页恰好一次，顺序与用户选择一致；保留源页到输出页映射 |
| E3 | 对所选页顺/逆时针旋转 90°，写入真实 PDF 页面方向 | 预览来自修改后 PDF 字节；保存后独立重新打开，方向与显示相符 |
| E4 | 每次有效编辑可撤销/重做；还原也是可观察的操作 | 修改历史有界；撤销后新编辑清空 redo 分支；保存后历史仍可使用 |
| E5 | 草稿受来源 SHA 与修订号约束 | 原件变化使草稿失效；旧 revision 请求不能覆盖当前草稿；错误/无变化请求不制造成功修改 |
| E6 | 明确确认后异步生成新副本，显示进度、失败、取消与输出 | 相同 revision 的失联重放返回同一保存任务；失败重试须明确发起；PDF 与证明按原禁止覆盖事务发布 |
| E7 | 保存结果可以在本机工作台重新打开 | 只能读取服务登记的输出及其冻结 SHA；不提供任意路径读取；检查真实输出页序、方向、标签与导航 |
| E8 | 普通带书签、内部链接、命名目的地和页标签的文档可处理 | 每项引用继续指向相同内容，页标签随来源页保留；不支持的目标编码或结构在处理前明确阻断 |

### 编辑专属复验

线性化继续使用其原有非目标语义及逐页显示不变合同。页面组织另建合同：按来源页映射核对实际输出；允许声明的顺序及旋转变化；其余内容流、资源、注释、导航和文档属性继续核对。归一化比较只能恢复明确声明的页树/方向/标签变化，不能删除任意语义键以换取相等。保存前重新打开输出，在固定参数下逐页比较预期方向的渲染和文本。

### 本阶段边界

先支持单文档完整页集的重排与旋转，不删除或复制页面。提取、拆分、合并、插入、书签编辑和批量初始视图仍在总产品范围内，后续沿同一编辑与副本模型推进；不因本阶段未实现而从产品规格删除。继续保留签名、加密、表单、附件及动态内容的既有改写守卫。

## 已复现的开发准入证据

- 同一计划含正常及损坏文件时，正常项虽为 ELIGIBLE，整批 COMPLETED_WITH_ERRORS 不保存可用计划，无法执行独立合格项。
- 原基线 `test_cancel_running_native_worker` 在本环境两次返回 OK 而预期 CANCELLED；`communicate` 成功返回后缺少取消复核。
- 原全文检索一次至多 2,000 页且无继续接口，片段取每页开头，可能与命中无关；大页超预算直接无法预览。
- 当前检查生产者已按规则合并 evidence，因此不能把 UI 的单次 find 单独宣称为已复现的漏项。新界面以完整证据渲染、去重页面定位和状态筛选提升可用性。

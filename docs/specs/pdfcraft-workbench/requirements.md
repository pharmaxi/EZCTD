## 目标

让临床 CRO 用现有本机工作台连续阅读长报告、定位检查证据，并处理含失败文件的批次。沿用 Python、PDFium、pikepdf 和原件只读/独立副本事务。主流程仍是选择实际持有的临床资料 → 阅读检查 → 查看修改计划 → 明确确认 → 生成并复验副本。

## 明确范围

本次不增加 PDFCraft/Rust 依赖，不引入付费 API、云上传或外部字体。沿用现有线性化副本能力；默认不删命名目的地、附件或字体，不做 OCR、通用内容编辑或有损压缩。PDFCraft 自检和本地自动测试均不代表官方规则等价、申报合格或 Windows/NAS 产品验收。任务历史限当前服务会话，不从旧 JSON 静默恢复可执行计划。

## 已复现的开发准入证据

- 同一计划含正常及损坏文件时，正常项虽为 ELIGIBLE，整批 COMPLETED_WITH_ERRORS 不保存可用计划，无法执行独立合格项。
- 原基线 `test_cancel_running_native_worker` 在本环境两次返回 OK 而预期 CANCELLED；`communicate` 成功返回后缺少取消复核。
- 原全文检索一次至多 2,000 页且无继续接口，片段取每页开头，可能与命中无关；大页超预算直接无法预览。
- 当前检查生产者已按规则合并 evidence，因此不能把 UI 的单次 find 单独宣称为已复现的漏项。新界面以完整证据渲染、去重页面定位和状态筛选提升可用性。

# EZCTD · 文件夹PDF批量检查与自动处理｜设计规格

**规格版本：1.0.0｜编写日期：2026-09-11｜状态：待实施、待产品验证**

仓库：`laojia-a/EZCTD`；本次只读基线：`682217846a49671c9ea8cea441eb7af88b11a161`。本规格不改变当前应用版本`0.3.0.dev0`，不代表新增功能已实现或获CDE认可。[S05]

三件套：`requirements.md`定义做什么与验收条件；`design.md`定义具体实现及操作边界；`tasks.md`定义任务依赖、阶段目标与完成证据。`supporting/traceability.json`是这些规格的结构化索引，不应直接覆盖现有生产规则文件。

## 1. 设计结论

沿用现有**Python本地服务＋浏览器工作台＋隔离PDF工作进程**，增加批次预设、逐文件自动管线和操作级复验。不要为本需求改成云端服务、微服务或完整eCTD发布系统。[S05]

本文件中“应”“新增”“拟”均是待实现设计。现有实现与计划能力按下表区分；来源[S05]是固定提交，不代表实施当天HEAD仍未变化。

| 位置 | 当前基线事实 | 本次增量 |
|---|---|---|
| `workspace.py` | 有目录发现、输入身份、逐文件任务及scan/plan/apply；实际plan/apply指向线性化 | 接入一次批次确认后的check→plan→apply→verify；不因一文件计划失败废弃其他文件计划 |
| `pdf_observer.py`、`assurance.py` | 有26项观察框架及有限检查；未证明穷尽的条件保留未判定 | 将事实提取、适用性、判据分开；逐项补齐完成条件，不靠增加结果行数宣称完整覆盖 |
| `copy_service.py`、`safe_io.py`、`read_scope.py` | 有原件只读、独立暂存、无覆盖发布与读取范围控制 | 复用并补齐原样复制、整批镜像输出、崩溃恢复及NAS发布能力探测 |
| `pdf_copy.py` | 受限线性化、严格重写护栏、对象图/文本/页面像素复验 | 保留线性化专用不变性检查；新增允许明确差异的修改复验，不能关闭原有保护 |
| `worker.py`、`process_runner.py` | 原生引擎位于有时限的独立工作进程 | 增加操作类型和阶段能力检查，保持父进程不加载PDF引擎 |
| `web/app.js`、`index.html`、`style.css` | 已有本地阅读、检索及任务界面 | 在既有页面添加预设、一次确认、按文件/问题视角及集中异常，不重做阅读器 |
| `pyproject.toml` | Python≥3.12；pikepdf≥10.5,<11；pypdfium2≥5.8,<6；Pillow≥11,<13 | 锁定实际通过回归的具体版本；OCR和PDF/A验证器作为独立可选依赖，不凭在线最新版文档假定已安装 |

建议新增的职责位置：`batch_pipeline.py`负责调度，`job_store.py`负责本机状态，`operation_registry.py`负责能力及操作契约，`operations/`放具体修改器，`verification.py`负责允许差异检查，`navigation.py`负责导航目标和反向引用，`ocr_adapter.py`/`font_provider.py`隔离可选引擎及字体资源。文件划分可在实现时微调，但接口、边界和验收不能消失。

## 2. 完整执行路径

```text
选定输入根、工作根、输出根
  → 枚举文件/角色覆盖/只读依赖 → 冻结清单和批次预设 → 一次确认
  → 对每个PDF：读取同一身份的字节
      → 提取技术事实 → 计算逐条适用性与检查结果
      → 为支持且已授权的操作生成计划
      → 无需修改：独立字节复制；只读阻断：保留原样并标明状态
      → 需要修改：私有暂存 → 执行操作 → 末端保存/线性化
      → 全部已批准变更复验 → 输出再检查 → 无覆盖发布
      → 记录文件终态 → 下一份；异常不终止其他文件
  → 根据所有实际输出重新验证跨文件目标
  → 汇总执行结果、逐条检查、未处理项、可交付范围
```

### 2.1 批次授权与自动化

用户确认的是**操作政策和输入范围**，不是每一个尚未发现的对象。批准预设可以表达：“对本批次普通临床PDF的所有合法XYZ书签目标，将缩放改为承前缩放；其余目标不改。”运行时计划必须证明某个对象符合该选择器，才能执行。不能把预设中的“修复链接”解释为任意删除、改目标、变更路径。

确认后，后台自动生成逐文件计划并执行，不再出现逐文件确认弹窗。新增清单外文件不自动纳入；源内容变化使该文件计划失效。用户补充密码、字体或目标映射时，为受影响文件生成新计划，并确认这一次新增政策；不要求重新批准全部成功项。

### 2.2 文件内部分操作与事务

计划阶段，不能执行的操作可进入待办，不阻挡独立且可以保全内容的已授权操作。例如字体资源缺失，但视图可安全调整，可输出“视图已调整、字体待处理”的副本。

**已进入执行计划的操作发生失败时，不发布该文件的半成品。** 回滚只丢弃本次私有暂存，保留原件；其他文件继续。需要接受一个更小操作子集时，重新生成明确的子集计划，不能在失败后悄悄把未完成动作当成功。恢复输出可为原样副本，但必须显示`UNCHANGED_WITH_ISSUES`，不是`MODIFIED_VERIFIED`。

### 2.3 操作顺序与冲突

| 顺序 | 操作 | 先后原因/冲突规则 |
|---|---|---|
| 0 | 输入身份、签名信号、凭据和资源检查 | 签名信号不能通过先解密或先清理规避 |
| 1 | 已授权解密、有限结构恢复 | 只在已支持且能建立保全基线时执行；不将恢复成功当全部内容已知 |
| 2 | 已确认方向处理、按需OCR、字体补嵌 | 页面及文字资源变化在导航定位/最终视图前完成；方向与OCR组合必须有已验证实现 |
| 3 | 明确批准的内容/附件/注释清理 | 对后续链接和属性的影响必须计入计划；隐藏字段并不等于安全清除 |
| 4 | 书签/链接路径、目标、唯一动作、承前缩放、映射创建 | 共享目标按所有者处理；同一字段收到冲突目标值时拒绝计划 |
| 5 | 初始视图、四项说明字段、需要的真实兼容处理 | 转换器若会重建内容或导航，必须前置到其依赖之前并重新检查；不能作为无害末端标签修改 |
| 6 | 最后一次保存及线性化 | 线性化之后不得再写元数据、书签、页码或其他对象 |
| 7 | 输出结构/变更保全/逐规则复检、整批依赖复查 | 验证消费最终发布字节，不验证中间文件后替换输出 |

操作使用`requires_before`和`invalidates_facts`描述依赖；配置只能选择已通过组合测试的操作组合。第一版组合按上述固定顺序运行，不建设任意用户脚本工作流。若版本转换器只能重绘或通用OCR工具会转PDF/A，则视为内容变换组合，必须单独通过验收，不绕过层级7。

## 3. 数据结构与稳定身份

所有下列结构都是**拟新增/扩展契约**。示例为合成说明，不是实际运行输出。

### 3.1 规则与上下文

`RuleProfile`包含`profile_id`、`version`、`effective_date`、26条规则、来源状态及内容摘要哈希。规则稳定键是`profile_id + rule_id`，不能只用整数26或标题。官网文件的SHA-256未取得就保持null；仓库旧哈希也不能替代本次来源取证。[S01—S03]

`DocumentContext`至少含：`module_node`、`document_role`、`language`、`foreign_reference_confirmed`、`paper_scan_policy`、`context_origin`。其中语言只描述语言，不能决定外文参考资料豁免。角色映射优先级：精确相对文件路径覆盖 → 最深已确认目录覆盖 → 批次明确声明 → UNKNOWN。

模块路径按数字段比较。例如`2.7.5`可以适用文献规则，`2.7.50`不是其子节点。文件名路径仅用于生成待确认候选，不从“英文”“reference”单词静默更改资料角色。

参考例外首先改变`applicability`，不停止只读事实观察。用户可单独自愿规范化豁免文件，但操作记录写`voluntary_normalization=true`，不能因此改写官方规则为FAIL。范围外文件默认不写；显式加入的依赖可读但不因此获得写入权限。

### 3.2 核心记录

| 模型 | 最小字段 | 关键约束 |
|---|---|---|
| `DocumentIdentity` | document_id、relative_path、size_bytes、source_sha256、snapshot_id | ID不等于basename；不把可见绝对路径发给前端作为读文件接口参数 |
| `BatchPreset` | preset_id/version、operations、selectors、context_policy、limits | 不保存凭据；未知字段和未支持操作拒绝，不能静默忽略 |
| `BatchConsent` | manifest_hash、preset_hash、context_hash、approved_operation_set、time | 确认后更改政策必须重新产生确认；不擅自扩展输入清单 |
| `Fact` | kind、value、object_locator、physical_page、extractor_version、coverage | 单纯未观察到对象不等于检查全部完成 |
| `RuleEvaluation` | rule_key、applicability、status、facts、reason、coverage、checked_sha256 | 检查结果绑定字节；官方观察独立字段存放 |
| `OperationPlan` | operation/version、selectors、preconditions、changes、invariants、dependencies | 精确到对象所有者/字段/页面，不允许“忽略全部元数据”这种宽泛复验豁免 |
| `DependencyEdge` | source_document/object、action_type、raw_target、resolved_identity、destination、state | 输入树可找到不代表输出树目标满足；目标依赖哈希变化会失效相关验证 |
| `VerificationEvidence` | input/output hashes、engine versions、allowed/observed changes、page coverage、checks | 保留未检查/超限/异常；证据不写密码，不宣称所有阅读器等价 |
| `FileResult` | check_before/after、operation_results、output_state、remaining_issues、dependencies | 支持“修改成功但还有问题”，不能挤进一个PASS布尔值 |

示例计划片段：

```json
{
  "schema_version": "1.0",
  "document_id": "doc-0007",
  "input_sha256": "<frozen-source-sha256>",
  "preset_hash": "<approved-preset-hash>",
  "operations": [{
    "id": "OP-BOOKMARK_ZOOM",
    "implementation_version": "<tested-version>",
    "owner_selector": {"outline_path": [1, 2]},
    "preconditions": {"destination_type": "XYZ", "complete": true},
    "expected_change": {"zoom_before": 1.5, "zoom_after": null},
    "preserve": ["page_target", "left", "top", "title", "unselected_owners"]
  }]
}
```

实际selector必须与源哈希、规范化对象身份及期望旧值一起使用；`outline_path`只是界面定位，不能在书签结构变化后继续盲用。不得把PDF对象或可执行函数跨IPC序列化到父进程。

### 3.3 三套状态与统计

| 层次 | 枚举 | 解释 |
|---|---|---|
| 规则检查 | PASS / FAIL / NOT_APPLICABLE / INDETERMINATE / NOT_RUN | PASS仅表示该有界本地判据完成，不是官方通过 |
| 操作 | PLANNED / RUNNING / APPLIED_VERIFIED / NO_CHANGE / SKIPPED / BLOCKED / FAILED / CANCELLED | 技术可处理、已授权和实际执行是不同维度 |
| 文件输出 | MODIFIED_VERIFIED / MODIFIED_WITH_ISSUES / UNCHANGED_VERIFIED / UNCHANGED_WITH_ISSUES / QUARANTINED / NOT_EXPORTED | “VERIFIED”表示已完成所述保全/有限检查，UI必须另示检查覆盖及剩余项 |
| 批次 | QUEUED / RUNNING / FINAL_CHECK / COMPLETED / COMPLETED_WITH_ISSUES / CANCELLED / FAILED | COMPLETED只在无未解释执行失败且报告持久化后出现；不要当合规结论 |

文件终态数量相加必须等于已批准清单数；已完成＋正在处理＋尚未处理也必须守恒。规则数/对象发现数/文件数分别显示。一个文件可有多个问题；不得把各规则文件数相加称为异常文件总数。

### 3.4 持久化与恢复

建议使用标准库SQLite记录**本机工作目录中的内部状态**，一个用户、一个活动批次、单个写入者；PDF输出和报告为不可覆盖发布。内部数据库更新不违反“不得覆盖用户输入/交付文件”，但不得在共享NAS上运行此状态数据库。无需引入云数据库或服务端账户体系。

`jobs`、`documents`、`plans`、`operation_runs`、`artifacts`、`dependency_edges`是足够的逻辑表；可以用JSON字段保存结构化详情。每个验证通过的文件为一个恢复检查点，OCR另可保存已验证页段检查点。状态写入、输出发布意图、发布完成记录应可识别崩溃窗口。

恢复前验证源/依赖哈希、预设、规则配置、引擎版本和缓存身份。任何一项变化，重算受影响结果；不把“路径一样”当缓存可用。重跑生成新run_id或受控恢复同一run_id，不覆盖既有交付产物。成功输出发生外改时标记`OUTPUT_CHANGED`，不得用它继续验证其他文件。

## 4. 检查器与修改器契约

建议一个固定注册表，不支持用户上传任意执行脚本。每个操作声明：版本、支持文档/目标类型、所需事实、允许写入字段、是否影响像素/文本/导航、排它条件、阶段、引擎依赖。

```python
# 接口示意，非本轮已经实现的可运行模块。
class PdfOperation:
    def inspect(self, session, request) -> dict: ...
    def plan(self, facts, preset, context) -> dict: ...
    def apply(self, session, plan) -> dict: ...
    def verify(self, before_session, after_session, plan) -> dict: ...
```

`session`只存在原生worker内部；父进程接受结构化摘要和阶段文件标识。所有路径由父进程在明确读取根内解析，worker仍校验其接收的冻结身份。所选操作尚未实现、依赖缺失或不支持组合时：只读检查照常，操作记录BLOCKED/UNSUPPORTED，UI不能让人误以为已经执行。

规则检查和修改器不是一一对应。例如6.19/6.21可共享授权解密能力，6.2/6.9共享路径模块；但输出必须各自有结果。反之6.20可拆成多个视图字段，不能只改PageMode便把全部6.20标通过。

## 5. 各类操作的具体设计

### 5.1 初始视图：6.20

有有效书签结构时计划`PageMode=UseOutlines`；没有书签时“仅页面”是材料明确展示的工程默认。`PageLayout`及放大率的默认表示必须用受控Acrobat样本和PDF对象核对，不直接把SinglePage或100%当成默认。[S03][S04，页23]

无OpenAction时不为了“默认缩放”添加第一页目标。对合法数组目标或单步GoTo动作，在支持策略内保留原起始页及现有位置、调整默认缩放；有脚本、多动作或不支持目标的OpenAction先报异常，不粗暴删除。Fit型初始目标若不能同时保留定位和准确表达默认，应记录不支持转换，不能返回误导性成功。

窗口居中、全屏、隐藏工具栏等作为独立ViewerPreferences选择器；“其他均默认”的经验需要转换为逐字段策略。不存在字段和已显式设置字段分开记录。应用恢复上次阅读位置可能影响显示，验收用新阅读会话，并同时读取文件保存值，不能只凭一次屏幕效果判断。

### 5.2 说明字段：EX-01

明确选择Info中的Title/Author/Subject/Keywords，同时协调对应XMP：`dc:title`、`dc:creator`、`dc:description`、`pdf:Keywords`；存在`dc:subject`标签集时，它与关键词的关联必须在预设里单独声明，不能因为字段名含subject就误清“主题”。清空标题应处理已批准的全部语言替代值，不能只清x-default而留下另一语言版本。[S07]

未选择的Creator、Producer、CreationDate、ModDate、PDF/A标识、版权及其他XMP不得被库的默认动作悄悄改变。实现应关闭自动编辑器标记/版本改写等副作用；确有必须变更的技术字段，须作为独立工程变更声明并纳入预设与证据。若无法精确保留，拒绝该输出。

元数据建议清理不等于完整去标识化或删除修订历史。仍声称PDF/A的文件在操作后需独立符合性复验；保留一个PDF/A标签不是已证明符合。

### 5.3 书签和链接解析：6.2—6.15

统一建立“导航所有者→动作→目标→文件/页”的图，保留对象原值和反向引用。书签所有者与页面Link注释分别统计。解析直接`Dest`、`A.D`、`AA`、`Next`、旧式Dests和Names树；有界遍历并检测循环。无法穷尽的分支明确未判定。[S06]

本地直接目标首项是有效页对象引用；GoToR直接目标首项是目标文件零基页号；远端命名目标在目标文件的名称表中解析后，是该目标文件的本地页引用。不能混用物理页、页标签和印刷正文页码。

合法XYZ目标需要完整参数结构。其zoom为null或0可表达保留缩放；数组缺失参数不是同一件事。数值必须合法、有限；不接受NaN、错误类型或无效页目标。修改明确XYZ时只改zoom，不改left/top。Fit/FitH/FitV/FitR等采用单独支持表：只有参数可以按批准策略映射且定位意义能验明时转换，其他进入待办。不能为提高自动修复率统一改到页顶。

命名目标及共享动作采取**所有者级写时复制**：改选中引用而不是原地修改共享对象；必要时为该所有者改用等义直接目标或唯一新名称，保留未选所有者行为。任何共享属性变化都应由反向引用测试证明影响范围。

多个动作的处理由唯一保留选择器决定，匹配不到或匹配多条即拒绝；不保留第一条凑数。既有`Dest`和`A`冲突也不能忽略其中之一。允许的GoTo/GoToR/Launch类型名单只是规则判据，程序一律不执行Launch或外部行为。[S03]

### 5.4 路径与目标映射

每个目标至少区分：AVAILABLE、MISSING_WITHIN_DECLARED_SET、NOT_PROVIDED、OUTSIDE_AUTHORIZED_ROOT、TARGET_UNREADABLE、MALFORMED、TARGET_NOT_EXPORTED。只有适用且确证违反判据时才报FAIL；缺资料和越界不可读不是已证实损坏。

相对路径允许指向批准范围内的兄弟目录，如`../appendix/lab.pdf`，不能一律禁止所有`..`；路径解析结果必须重新通过读取根检查。绝对盘符、UNC、file URI或外部URL不能触发网络挂载/全盘搜索。Unicode文件规格、大小写、Windows保留名及URL编码不得用一次字符串替换处理；标准化仅用于明确识别，不改变原意。

路径映射以明确的源路径/文件身份→目标相对路径为准。两个同名文件不是自动匹配证据。用户确认一个目录迁移规则后，匹配唯一且目标身份已验证的文件可批量处理。

所有来源文件完成后，以**实际最终输出集合**再解析一次。输出中移到`unprocessed/`的不可读文件不算已满足链接目标；只读参考根中存在、但用户没有批准复制的目标也不算输出依赖满足。最终检查可以改变可交付状态，但不得在报告阶段偷偷回写PDF；需要修改就重新进入修改、末端保存和复验。

### 5.5 外链移除、导航创建、外观

移除外链是处理PDF真实动作/注释，不删除普通文本中的URL、邮箱、DOI。阅读器从URL自动产生可点击效果是材料页28的应用偏好，不应当作修改失败或实际已删除PDF链接。[S04]

有子节点的外链父书签不得只清除动作留下新的失效节点。策略须明确：重定向；提升子节点并移除父节点；或用户确实批准删除整个子树。无明确策略则集中待办。

创建书签或链接基于已确认的标题/热区/文件/物理页/坐标映射；自动标题提取可提出候选，不自动构成业务正确目标。6.23检查的是书签存在要求，产品不应插一个“首页”占位书签冒充完成实际导航整理。[S03][S04，页31—33]

外观颜色/边框仅可选项，不是6.x要求；有可见边框的删除或更改属于批准的局部视觉变化。链接Rect/QuadPoints与目标定位分别保存，不把正文文字变成链接对象后重写原文本。

### 5.6 搜索性与OCR：6.25

先做逐页分类：原生可提取文本、纯扫描疑似正文、混合页、已有OCR、空白、图表无正文、乱码/映射异常、检查未完成。只有有字符并不能证明正文可搜索；仅页眉有文字的扫描正文不能整页通过。自动判定需保存页面级依据及未覆盖区域，低置信度进入疑点集合，不靠OCR先改完再掩盖分类不足。

材料页16使用“可编辑的文本和图像”，并设置缩减像素采样600dpi；页18—19指出内容丢失和字体重叠等风险。本产品默认候选方案是**保留原可见内容、仅为批准页面增加不可见可搜索文字层**，这是工程决定，不是材料原句。禁止把插值600dpi当成恢复原始清晰度。[S04]

OCRmyPDF为可调研候选，不预设其当前安装、许可或全部Windows打包能力。引擎适配器应固定版本、语言资源、输出格式、优化及重做策略；没有明确授权时不得全文件PDF/A转换、图像重编码、删除矢量/原生文字、去噪或重排。[S09]

首个可运行范围应至少覆盖清晰的纯扫描页面；混合页支持“明确区域且无原生正文被替换”的路径。已有正常OCR不重做；低清、手写、重叠文本和不支持的复杂混合页在集中复核中呈现具体原因，不伪造修复成功。

分块运行按页或页段保存可恢复状态，默认一个OCR工作进程。超时/取消不发布半份PDF。拼回文字层时保留原页对象/目标和未处理页，不能拆成图片重组后丢失书签。组合完成重新检查字体及目标。

OCR复验至少分两层：

- 技术：目标页有可提取文字、位置可定位；原图像/矢量/原生文字及未选页未误改；无缺页或重叠新增可见字。
- 转录质量：与合成真实标注样本或用户核实原图比对。数字、单位、日期、编号与希腊字母/上下标另列疑点。普通真实文件没有转录真值时，不可自动给“内容准确”结论，也不把新OCR文本当原始临床数据权威。

所有图文仅本地处理，不为消除识别错误调用默认云模型，更不能让AI自动纠正数值。

### 5.7 字体：6.26

标准字体名单来源[S03]，不能替换成PDF Base-14。保存原始BaseFont、去子集前缀后的名称、字体类型、实际使用页/对象、嵌入或字形资源、ToUnicode及别名判定状态。SimSun等名称别名的监管等义性未确认时不得仅凭猜测豁免；也不能把严格名称不匹配直接说成已证实缺字。

资源遍历覆盖继承资源、内容实际调用、Form XObject、注释外观及其字体；资源仅声明未使用与实际使用分开。遇到资源循环/损坏/解析上限保留未完成覆盖，避免未见字体就全部PASS。

Type3按CharProcs及引用资源检查其字形定义，不套用必须存在FontFile的普通字体判据。材料页20的Type3“未嵌入”是培训截图个案，不能升级为通用算法。Type0/CID后裔字体、字形映射和Unicode另行检查。[S04][S11]

本地字体提供器仅读取用户指定的授权字体目录。必须核对字体名/具体版本、字形索引或编码映射、字宽、所需字符覆盖和嵌入权限；不按视觉相似、中文字体家族相近或文件名近似自动替换。不复制字体文件到GitHub或提供给其他用户。

补嵌先交付清晰限定的TrueType与中文CID样本路径；超出支持类型给资源/转换需求，不能宣称通用补嵌。输出复验字形、字宽、行布局、数字单位、文字提取和页面显示。使用PDF引擎能够显示不证明独立环境无替换字体；需记录实际使用/回退信息，至少用固定字体环境样本对照。

OCR新增的字体必须再检查；“修复潜在字体问题”命令退出成功不是嵌入成功。[S04，页21]

### 5.8 密码、签名与扫描签章

先检查数字签名结构信号，含空签名域、ByteRange等；存在信号继续只读，禁止任何重写/解除密码以规避签名。这里只判断结构保护性信号，不提供密码学有效性结论。[S05]

用户必须明确有权解除相关安全限制并提供实现所需凭据。口令只在当前进程生命周期的受控通道中传入worker，不放URL、命令行、预设、日志、报告或故障包；需要临时凭据文件时用独占权限和短寿命，并说明本机边界，不承诺SSD可证明擦除。错误凭据按文件/凭据映射进入异常，不自动暴力尝试。

纸质签章扫描件没有数字签名结构信号，并不意味着可自动修改。批次声明可以一次选择允许原貌保全技术处理，或要求字节不变；目录/文件可覆盖。用户未确认的扫描签章材料保留只读；系统不得通过图像判断“这里没有印章”而自动放行。普通原生文本文件不因缺少扫描签章声明被统一阻断。

### 5.9 附件、注释与动态内容：6.17、6.18、6.24

附件检查含Names/EmbeddedFiles、AF、文件附件注释、嵌套文件规格及对象层关联；不得只检查页面上是否出现回形针。删除按明确选择器，引用同步调整，独立提取物保存在私有或显式隔离位置，不作为新PDF交付内容。正文末尾附录页不是嵌入附件。[S03]

注释按Subtype分类。第一批清理仅支持普通便笺等明确类型；Link保留，Stamp/Widget/Redact等不能套“删除所有注释”。Redact标记删除和实际删密内容不是同一能力，本规格不做通用内容删密。可见注释删除需明确的局部视觉差异授权，且底层正文不得变化。

动态对象静态观察，不执行脚本、媒体、Launch或自动展开附件。允许清理的已知无可见副作用脚本位置须列支持表；动态表单、3D或媒体无法确定保全时保持未支持，不默认栅格化整个文件。6.18是提示信息、6.24是警告，不因此降低删除操作的谨慎程度。[S03]

### 5.10 版本及结构修复：6.16、6.1

PDF头、Catalog版本和实际特性需要分开观察。版本2.0不能只写回1.7头就算兼容转换；PDF/A声明不等于符合性。符合性验证器应固定版本和验证profile，存在修改后重新验证；引擎不具备所需能力时保持未判定，不假称通过。[S07][S08]

转换器必须给出支持矩阵和副作用，保留页面/文本/导航要求与其他操作相同。凡依赖重绘、字体替换或整页栅格化的通用转换，默认不进入自动处理范围。

结构恢复仅支持被固定测试覆盖、且能以独立方式建立内容基线的故障类型。损坏原件中无法确认的内容，不可用恢复输出自证未丢失。禁止删坏页、补空白或“能打开即可成功”的规则。

### 5.11 方向与最终线性化

方向只处理已批准物理页及90度步进旋转，保留原有CropBox、Rotate和坐标空间信息；不是统一A4、裁边、页序重排。热区和目的地坐标是否需变换取决于具体采用的页面变换表示，必须用原生样本验证，不能不分情形把所有坐标乘同一矩阵。[S04，页27]

线性化使用既有安全副本路径，在所有变更之后进行。检查不能只用`is_linearized`标记，需核验实际线性化结构；最终文件后续任何写入都触发重新保存/线性化/验证。无需修改且已符合所选操作目标的文件采用原样独立复制。[S05][S08]

## 6. 复验方法：明确允许差异，不取消检查

现有线性化以规范化对象图不变、文本/几何/像素相等验证。新增属性修改必然改变部分对象，因此使用**按操作批准的差异集合**，而不是全局忽略Outlines、Metadata或Annots。[S05]

| 修改类型 | 允许变化 | 必须保留与复验 |
|---|---|---|
| 原样复制 | 无字节变化 | SHA-256相同；独立目标文件；输出路径正确 |
| 纯属性/导航缩放/线性化 | 明确批准字段及必要结构记账 | 页面内容流、图像、字体、提取文本、几何、标签、未选导航；全页固定参数渲染比较 |
| 元数据 | 四项选择字段及预先列明技术字段 | 未选Info/XMP、页面及导航；PDF/A仍需独立评价 |
| 批准注释/外观变化 | 对应对象及已批准可见区域差异 | 正文内容流不变；非批准区域/对象保全；允许区域也不能藏正文数字改动 |
| OCR | 批准页新增不可见文字层及必需字体 | 原图像/矢量/原生文字保全、未选页不变、页数/目标不变；转录质量另报 |
| 字体补嵌 | 精确字体资源加入及必要引用 | 原字符语义、字形、宽度、行布局、全部数值与显示一致；不接受替换字体 |
| 方向 | 明确物理页变换及必要坐标同步 | 对照预期旋转后的显示/点击位置；其他页、正文字符和目标含义不变 |
| 真实格式转换 | 仅支持矩阵声明的表示变化 | 内容及导航等价需独立确认；不因对象重建而跳过语义复验 |

流程：先验证计划旧值仍成立→执行→重新解析输出→计算实际变更→验证变更恰好落在批准对象/字段内且新值准确→检查未批准部分→渲染/文本/导航/适用规则复检→生成证据。凡不能解释的对象变化、文本变化或字段丢失均拒绝发布该候选。

默认复用150dpi全页渲染用于明确的非视觉操作回归；这是工程参数，不是证明所有阅读器/所有分辨率等价。超过单页像素或其他限额时标复验未完成，不能自动抽查几页后仍写全页通过。渲染设置含注释/颜色/旋转参数及引擎版本必须保存，避免因环境漂移误判。[S05]

图像像素一样不证明链接目标、文字映射或隐藏文本一样；文字提取一样也不证明原图片和页面布局一样。三类证据不能互相替代。

## 7. 文件、输出和安全发布

### 7.1 目录设计

```text
<用户输入>/                         # 只读
<明确只读依赖>/                     # 不默认复制、不写
<本机工作目录>/
    state.sqlite
    cache/<identity>/
    staging/<run-id>/<doc-id>/       # 半成品不可作为交付文件访问
<输出根>/<唯一run-id>/
    pdf/<原相对路径>.pdf             # 已验证改写、可读原样副本
    unprocessed/<原相对路径>.pdf     # 不可读/需密码等原字节副本，明确未核验
    reports/
        manifest.json
        results.json
        report.html
        evidence/<doc-id>.json
```

输入根、工作根和输出根互相隔离，检查祖先/后代关系及平台路径别名。用户选定输出目录存在并非覆盖许可；每次新run，精确目标文件已存在即冲突。输入硬链接、符号链接、Windows重解析点/UNC权限在实际读取时复核，不把首次路径检查当永久授权。

可读但某操作被阻断的文件允许按原字节独立复制到pdf并显示未处理原因；不可读/未知密码文件在unprocessed。若用户要求不导出某阻断原件，则NOT_EXPORTED，并传播依赖影响。不要为了维持相对链接偷偷把文件从隔离区当成已合格目标。

非PDF文件不默认处理。作为链接依赖确需交付时，只支持用户明确批准的原样复制白名单/清单，不宣称检查其内容；这不扩展成SAS/XPT/Excel编辑功能。

### 7.2 发布事务

先在输出文件系统允许的私有暂存位置形成PDF和证据，重新校验源身份，按无覆盖语义发布。可复用已验证的“stage→新目标硬链接”方法，但这个硬链接源必须是私有stage，不能是用户输入。跨文件系统/NAS不能默认具有同等行为。[S05]

发布意图先持久化；PDF及证据都成功且最终清单记录完成后，才对外显示“发布成功”。崩溃后可识别属于本次的半发布产物；只允许清理能通过run记录与文件身份证明是自己创建的对象，不能删除现存同名文件。证据写失败必须撤回本次候选成功状态，原件和其他文件不受影响。

对无法证明安全无覆盖发布的NAS配置，不提供“尽力覆盖”降级。提示输出到本地安全目录，再由用户批准的独立交付复制完成NAS写入及校验；NAS支持状态明确为未验收/不支持，不能与本地能力混算。

## 8. 工作台与接口

### 8.1 用户界面

保持阅读字体和基本页面工作区，新增顶部三个主要操作：**导入文件夹、检查/按预设处理、查看输出**。预设选择处展示实际启用操作及未安装依赖；不是把30个工具按钮全部铺在首页。

“按文件”表至少显示相对路径、角色、处理进度、可自动处理项数、已改动作数、剩余问题和输出状态。“按问题”按6.x/经验操作分组，可筛文件、查看页/对象、批量补映射或选择策略。一次补充应用于所选唯一范围，不弹几十次同类确认。

详情用原值→计划值→输出值三列；旁边保持PDF定位/阅读。原官方报告观察放独立页签并标来源版本，不覆盖当前检查。运行可离开详情页，但暂停/取消/关闭浏览器和关闭本地服务的含义要区分。

### 8.2 拟新增接口（不是当前已可调用的端点）

可在既有路由下等价实现；以下约定用于前后端验收：

| 方法/路径 | 输入 | 输出及约束 |
|---|---|---|
| POST `/api/v1/batches/prepare` | 已建立工作区ID、文件选择、预设/上下文 | manifest/preset摘要、待确认政策和支持情况；无真实修改 |
| POST `/api/v1/batches/start` | prepare_id、确认的摘要、mode | run_id；一次启动后台逐文件执行 |
| GET `/api/v1/batches/{id}` | run_id及分页参数 | 进度、守恒统计、终态；不返回密码 |
| GET `/api/v1/batches/{id}/files` | 筛选和分页 | 逐文件检查与操作结果概要 |
| GET `/api/v1/batches/{id}/issues` | 规则/错误类别筛选 | 集中异常及所需输入，链接为安全定位标识 |
| POST `/api/v1/batches/{id}/cancel` | run_id | 请求取消；不能立即谎称已安全停止 |
| POST `/api/v1/batches/{id}/retry` | 所选异常、补充映射或不含明文的凭据引用 | 新计划/恢复确认信息；哈希变化必须重新准备 |
| GET `/api/v1/capabilities` | 无 | 引擎可用性、具体支持矩阵、版本、限制 |

路径来自已确认的Workspace及DocumentID，不接受任意用户传入绝对路径直接读盘。错误信息和HTML报告正确转义；HTTP服务保持本机范围和既有CSRF/CSP等保护，不执行导入报告脚本或PDF动作。[S05]

### 8.3 错误分类

| 代码 | 用户含义 | 自动行为 |
|---|---|---|
| SOURCE_CHANGED / OUTPUT_CHANGED | 输入或已完成输出已变化 | 使相关计划/依赖验证失效，要求重新准备 |
| CREDENTIAL_REQUIRED / WRONG_CREDENTIAL | 缺少/错误凭据 | 集中待补充，其他文件继续 |
| SIGNATURE_BLOCKED / SCAN_POLICY_UNCONFIRMED | 签名保护或扫描签章口径未确认 | 不重写，可原样保存并标明 |
| FONT_RESOURCE_MISSING / FONT_MISMATCH | 缺少精确字体或资源不匹配 | 不替换；保留可用其他操作结果 |
| TARGET_NOT_PROVIDED / TARGET_NOT_EXPORTED | 目标未提供或未进入交付树 | 报依赖问题，不猜目标，不删除导航 |
| UNSUPPORTED_DESTINATION / CONFLICTING_POLICY | 目标或策略超出支持范围 | 跳过未进入计划的操作；冲突计划拒绝 |
| VERIFY_UNEXPECTED_CHANGE / VERIFY_INCOMPLETE | 未授权变化或复验不完整 | 不发布候选副本；记录具体层次 |
| OUTPUT_EXISTS / UNSAFE_PATH | 覆盖/越界风险 | 不写入、不删除其他文件 |
| RESOURCE_LIMIT / ENGINE_TIMEOUT | 资源限制或超时 | 可取消/重试，未完成检查不改成FAIL或PASS |
| PUBLICATION_FAILED / DISK_FULL | 发布或磁盘失败 | 保留可解释状态，不计成功 |

## 9. 性能、运行边界和隐私

默认逐文件串行；可选少量并发只在内存/CPU及原生引擎验证后开放。OCR与页面渲染限制单独配置，禁止同一个原生PDF对象跨线程共享。现有200MiB/文件、2000页及像素限制是工程防护，不是本章CDE监管阈值；显示限额及越限原因，并允许经过实测的配置扩展。[S05]

目标：任务创建后先显示已知扫描进度，长任务持续提供文件/页段状态，取消在受控工作进程终止与清理后反馈。性能基准必须记录设备、磁盘/网络、样本复杂度、版本、页数和实际用时；不承诺任意PDF固定秒数。IT-33是测量计划，尚无实測结果。

独立进程和超时不是完整OS内存/网络沙箱。若增加Windows Job Objects等OS机制，须单独实现和验证，不能预先写“已完全隔离”。无默认遥测和云OCR；本机临时数据按保留策略清理，不在导出故障包中附带真实PDF、字体、正文或明文绝对路径。

### 9.1 工程验收目标（待实测，不是当前能力声明）

在M6登记的基准设备上，任务被服务接受后2秒内返回run_id或明确拒绝；长任务至少每2秒提供状态心跳（可为“仍在处理”，不得伪造页进度）。取消请求确认后目标10秒内停止所属worker树或报告具体终止失败；子进程无法停止时禁止同文件重新执行和发布半成品。

默认一个文件worker、一个OCR任务；文件级数量上限沿用已确认产品限额并测试边界，禁止通过同时开启大量worker提高表面吞吐。100文件批次用于操作完整性验收，100份20页文本、500页扫描和高分辨率大图用于性能测量；这些是测试规模，不是任意真实PDF都能在固定时间内完成的保证。

必须满足的正确性指标：输入未授权变化为0；覆盖既有输出为0；已完成支持范围内的未授权对象/字段变化为0；批次状态统计差额为0。OCR转录准确率只对有独立真值的测试集统计，公开样本定义及错误类型，不用“99%准确”作为未测默认值。

## 10. 测试、迁移与发布

### 10.1 测试层次

单元测试验证适用性/状态/选择器/路径语义；合成原生PDF测试验证读写和保全；浏览器测试验证一次确认、筛选、定位、异常和输出；实际Windows/NAS测试验证系统路径和发布。四层不可用stub互相替代。

每规则P/N/U用例定义在`requirements.md`及结构化索引，集成IT用例在`tasks.md`。可复用已有测试，但每项必须指向新的固定提交及实际报告，不继承历史通过数。

初始回归使用仓库现有命令，例如：

```bash
python -m pytest -q tests/cro_pdf

```

新增测试文件路径在实现时按模块确定；不存在的测试不可在记录中写成已运行。现有CI入口继续使用`artifact-integrity.yml`等已确认流程，不为每一轮小修复另造v2/v3工作流。[S05]

### 10.2 兼容和迁移

保留旧报告导入与旧scan CLI；新增batch模式不改变旧报告身份。旧4.x材料观察不能简单改前缀导入6.x，应保存旧rule_key、来源类型及明确crosswalk。当前runtime中的6.x编号保持稳定，修正的是旧规格/材料主索引，不进行一轮“全库4改6”字符串替换。

规则数据建议单一可维护来源并在构建时产生runtime资源；当前仓库同时存在rulepack及包内资源时需检验同步，不让两套规则静默漂移。对本次范围不适用的历史研究文档保持归档，不删去其来源或改写成已通过证据。

新增能力按阶段注册开关：未有原生测试和UI交付的操作在capabilities为NOT_READY；不允许UI提前给出“自动修复成功”。应用版本只有实现发布时才提升，本规格不把0.3.0.dev0改成已发布的新版本。

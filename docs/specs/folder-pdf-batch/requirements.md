# EZCTD · 文件夹PDF批量检查与自动处理｜需求规格

**规格版本：1.0.0｜编写日期：2026-09-11｜状态：待实施、待产品验证**

仓库：`laojia-a/EZCTD`；本次只读基线：`682217846a49671c9ea8cea441eb7af88b11a161`。本规格不改变当前应用版本`0.3.0.dev0`，不代表新增功能已实现或获CDE认可。[S05]

三件套：`requirements.md`定义做什么与验收条件；`design.md`定义具体实现及操作边界；`tasks.md`定义任务依赖、阶段目标与完成证据。`supporting/traceability.json`是这些规格的结构化索引，不应直接覆盖现有生产规则文件。

## 1. 产品目标与不变范围

导入一个实际持有的临床资料文件夹，递归发现PDF，**逐文件检查、按一次确认的批次预设自动修改、逐文件复验、保持目录结构输出**；正常项无人值守执行，异常集中处理，不要求逐文件打开属性窗口。

处理范围固定为**模块5、模块2.5、模块2.7**。用户不需要提供完整申报包、`index.xml`、`cn-regional.xml`、STF或有效`0000`序列。模块范围是资料内容边界，不是目录必须按某种形式命名。英文临床报告、空腹/餐后BE报告、方法验证/样品分析、普通附录，以及2.7.5/5.4参考文献可在同一批次中出现；实际规则适用性由显式资料上下文判定。

不纳入本轮：模块1/3/4处理、完整eCTD Publisher、申报序列/生命周期组装、Word转PDF、PDF合并拆分/A4缩放、任意正文编辑、自动删除封面、云端AI纠正临床数据、电子签章生成、自动破解密码。读取已有报告只是辅助，不成为开始检查的前置条件。

## 2. 规范与材料关系

### 2.1 本次采用的正式规则基线

CDE官网2026年第4号通告在2026-01-15发布V3.2.2相关技术文件，列有附件4《eCTD验证标准V1.1》，并规定2026-03-01施行。[S01] 本次核读同名公开PDF副本物理页9—11，其PDF分析为**6.1—6.26**，不是材料的4.1—4.24。[S03]

本次采取“官网通知及附件身份已核实＋公开副本表格交叉核对”的证据状态；官网附件本轮未成功取得，尚无新下载官网原件哈希，不宣称字节级一致验证完成。该缺口不阻止以已核对规则编写和实现PDF功能；实施时补取来源证据，若正文有差异则先比较再变更配置。[S02]

只采用本次能够核实的正式V1.1基线，不把v4.0征求意见材料混作现行要求。编号“6”是验证标准的**章节**，与待处理资料的“模块5/2.5/2.7”不是同一维度。[S01][S03][S10]

### 2.2 实际影响与最低纠正

主编号统一为6.x；旧4.x只作材料出处索引。6.18注释和6.22快速Web查看进入正式清单；6.23对适用文件使用“超过5页需要书签”的现行含义，不沿用材料的“建议”。6.24是脚本/3D/动态内容规则，旧4.8只作主题映射，不把材料权限截图视为完整解释。[S03][S04]

严重程度保留：**16项错误、8项警告、2项提示信息**。严重程度、自动修复风险和产品执行状态分开；“提示信息”不等于可无条件删除对象，“错误”也不等于软件能够自动决定正确目标。

### 2.3 模块内的例外

| 条件 | 本规格内执行规则 |
|---|---|
| 普通5、2.5、2.7临床PDF，角色已确认 | 逐条执行6.1—6.26的相应检查 |
| 已确认2.7.5或5.4参考文献，或外文参考资料 | 对6.2—6.20、6.22—6.26使用其相应文献豁免；6.1和6.21仍执行 |
| 申请表角色 | 6.23另有例外；本产品不因此扩展到模块1。CRF/病例报告表不能当成申请表 |
| 资料上下文未知 | 继续提取技术事实；需要上下文的规则为未判定。可通过批次声明/目录覆盖一次解决，不强制逐文件标注 |
| 一个CSR内部含参考文献章节 | 不把整份CSR自动标作文献；例外基于文件所归属的资料角色/章节 |

规则原文还列有模块1的线性化例外，以及3.3/4.3文献例外，配置保留原始语义，但这些模块不是本轮可写入范围。[S03] 任何文件豁免均不等于允许执行脚本、越权读取链接或改写数字签名。

### 2.4 标准字体数据（名称而非字体文件）

6.26列明的16个名称为：宋体、黑体、Times New Roman、Times New Roman Italic、Times New Roman Bold、Times New Roman Bold Italic、Arial、Arial Italic、Arial Bold、Arial Bold Italic、Courier New、Courier New Italic、Courier New Bold、Courier New Bold Italic、Symbol、Zapf Dingbats。[S03] 保留原名单；不以Base-14列表替换，不附带或传播字体文件。

## 3. 用户工作流

1. 选择输入文件夹及独立工作/输出位置；程序显示PDF数、目录和不可访问项。
2. 选择“仅检查”或“按预设检查并自动处理”；一次确认范围、普通资料声明/文献覆盖、启用操作及扫描签章口径。
3. 系统对每份文件提取事实、判规则适用性、生成内部修改计划，自动执行满足支持条件和授权的动作；不另弹每文件确认。
4. 在私有暂存副本上复验；成功则发布输出。可处理动作完成但仍有其他问题时显示“已处理，仍有待办”；不能标全面通过。
5. 无需修改文件原样复制；失败、保护性阻断和未知项集中分组，其他文件继续。
6. 全部最终输出确定后复查跨文件引用，输出汇总和剩余事项。用户补映射/字体/凭据后重跑受影响项，成功项不重复无谓改写。

**仅检查模式不输出改写PDF，也不默认为交付复制全目录。** 检查并处理模式才创建交付镜像。自动化意味着一次授权后按确定规则执行，不意味着自动猜业务目标或跳过复验。

## 4. 跨功能需求及验收

### FR-001 · 模块及输入边界

**要求：**用户选择的处理范围仅为模块5、2.5、2.7的PDF；无需完整CTD目录、XML、STF或0000序列。目录命名用于候选提示，不静默证明模块归属。

**验收：**导入只含5.3.1.2报告的任意命名目录即可检查；2.50不得因前缀被识别成2.5。

### FR-002 · 文件夹递归与快照

**要求：**递归枚举.pdf（大小写不敏感）及必要文件头验证，生成相对路径清单；哈希绑定实际消费字节，检测扫描/处理期间变化。

**验收：**重复文件名分目录保留；坏后缀/访问失败/新增文件有明确状态，不静默漏掉。

### FR-003 · 一次确认自动执行

**要求：**提供仅检查及按预设检查并处理；启动时确认一次输入清单和预设授权，逐文件自动生成计划并执行满足条件的动作，不弹逐文件确认。

**验收：**一份需要密码的文件不阻断其余文件；已有映射/授权的同类问题自动处理。

### FR-004 · 现行规则和来源

**要求：**界面、API、报告以6.1—6.26及固定profile为主；材料4.x仅保留crosswalk；规范要求、经验建议和工程决定分字段记录。

**验收：**全部26条有severity、applicability、来源定位；不把6.18/6.22改成错误。

### FR-005 · 批量上下文及逐条例外

**要求：**支持批次普通临床资料声明和子目录/精确相对路径覆盖；2.7.5、5.4参考文献及已确认外文参考资料逐规则豁免；未知角色不猜。

**验收：**英文研究报告仍按普通报告；参考文献有打开密码仍执行6.21；2.7.50不得误豁免。

### FR-006 · 每条规则可解释

**要求：**每文件26条均记录PASS/FAIL/NOT_APPLICABLE/INDETERMINATE/NOT_RUN、原始事实及完成度；没有发现问题不能替代穷尽检查。

**验收：**超时的字体检查显示未判定；页面/对象位置可点击定位；输出不宣称官方通过。

### FR-007 · 预设及选定范围

**要求：**内置保守的临床属性预设；元数据、OCR、精确补嵌、删除/移除、密码解除分别显式选择；规则豁免不等于禁止用户自愿标准化。

**验收：**重开后复用不含密码的版本化预设；未知操作键拒绝；选择性修改不会波及未选对象。

### FR-008 · 原件只读与无覆盖输出

**要求：**输入及只读依赖不写入；工作区/临时区/输出树与输入树分离，不覆盖既有输出，不以指向原件的硬链接交付。

**验收：**输入哈希全部保持；目标已存在时报冲突；Windows别名/重解析点越界被拒绝。

### FR-009 · 输出目录与未改文件

**要求：**保留批准交付范围的相对路径和文件名；无需改的PDF进行独立字节复制；未改、已改但有问题、阻断、未导出分别记录。

**验收：**合格附件未需改仍在输出树；输出不是只含被修改文件；不可读/打不开原件置未处理隔离树而不伪装可交付。

### FR-010 · 最终依赖复验

**要求：**在全部文件最终输出确定后，以输出根重新解析跨文件导航；外部只读依赖可用于诊断，但未纳入输出不能算交付目标已满足。

**验收：**指向未导出文件显示TARGET_NOT_EXPORTED；修改目标文件后回查所有已知来源链接。

### FR-011 · 异常集中处理与重跑

**要求：**文件失败不中断批次；按缺少密码/字体/映射/复核分组；补一次信息后重跑受影响项和依赖项，不重做所有成功文件。

**验收：**新增映射只重跑相关文件；源哈希变化时旧计划失效，不复用过期OCR结果。

### FR-012 · 进度取消与恢复

**要求：**显示文件级及页段进度；取消不发布半成品；应用中断可识别恢复点；自动网络轮询/未来定时运行不在本规格中。

**验收：**终止OCR后保留已验证文件；重启校验输入/配置/引擎版本后从安全检查点继续。

### FR-013 · 按操作验证改动

**要求：**每种操作定义允许改动的字段、对象及页面；所有未批准改动必须使该候选输出不被发布。

**验收：**只改视图时偷偷改正文数字/隐藏链接/删书签必须被拒绝；不是只看像素。

### FR-014 · 读图文本与OCR分层

**要求：**不把存在文字等同全页正文可搜索；OCR技术可搜索性与识别内容正确性分别评价；受试者编号/数值不由AI自动修订。

**验收：**既有数字文本字节/提取值不变；低质量OCR显示待复核而非全部正确。

### FR-015 · 安全与签章

**要求：**任何数字签名结构信号默认阻断重写；扫描纸质签章按批次业务声明选择允许技术处理或保留字节；不通过图像识别擅自判断。

**验收：**签名文件原样复制并保留阻断原因；解除密码也不能删除签名；扫描件未知口径只读。

### FR-016 · 本地数据及凭据

**要求：**文件、OCR结果、截图及字体仅在明确本机/授权NAS范围处理；无默认云API；不上传真实资料；密码不落日志/预设/报告。

**验收：**断网仍能做已安装的基础功能；技术依赖安装另行告知；故障包默认不含PDF/正文/绝对路径。

### FR-017 · 结果工作区

**要求：**按文件与按问题两种视角；原始值→计划值→输出值、已改动作与剩余问题分栏；保留已有阅读/搜索能力，不改造成重型编辑器。

**验收：**点6.15定位具体页热点，批量筛选可处理项；无需逐个打开属性对话框。

### FR-018 · 可测能力而非泛化承诺

**要求：**检查器、修改器、官方对照、Windows/NAS环境验收分别标状态；研究中的能力在UI禁用且说明原因，不能以空实现打勾。

**验收：**26条都列出但部分未完成时显示真实覆盖；仅完成结构检查不标所有内容正确。

### FR-019 · 资料角色与处理授权分离

**要求：**规则不适用、技术可修改及用户允许修改是三个维度；参考文献可以有技术问题但默认不强制改；允许Launch不等于允许执行。

**验收：**豁免文件记录NOT_APPLICABLE且可原样交付；用户自愿标准化留独立操作记录，不改成规则FAIL。

### FR-020 · 有限资源及操作顺序

**要求：**默认逐文件串行、OCR受限并发；先需用的解密/结构处理、页面处理/OCR/补嵌，再导航/属性，最后线性化和最终复验。

**验收：**500页文本文件不做OCR；资源超限可解释且不中断批次；限额标工程限制，不混作监管阈值。

## 5. 26项规则逐项规格

以下规范要点为摘要，不替代[S03]正文；“检查/自动处理/异常/保全”均为工程实现要求。P/N/U是待实现的正例、反例和边界/未判定样例，尚未执行。`REF`等例外代码见第2.3节及结构化索引。

### R-6.1 · 可读性

| 属性 | 规格 |
|---|---|
| 现行规则/严重程度 | 6.1 / 错误；来源[S03] |
| 材料定位 | 旧号4.1；物理页13；映射性质`FUNCTIONAL_CROSSWALK` [S04] |
| 规范要点 | 检查损坏、不可读或零页PDF。 |
| 适用性代码 | `ALL` |
| 检查 | 严格解析、页树/内容流检查；记录全页渲染完成数和具体失败页。恢复模式可读与严格解析可读分别报告。 |
| 自动处理 | 默认只检查；M5仅对可用独立证据证实内容保全的结构修复生成副本。 |
| 异常及不足 | 密码导致打不开由6.21单列；缺少解码器/超限/检查中断不是已证明损坏。无法建立内容基线时不自动重建。 |
| 不得误改 | 不得删页、补空白页或用首页能显示替代全页检查；恢复输出不得标为“原件内容已完整确认”。 |
| 操作/阶段 | `OP-READABILITY` / M1；检查和修改完成状态分别记录 |

- **AC-R61-P（正例）：**3页合成文本PDF逐页可解析且可渲染。
- **AC-R61-N（反例）：**零页PDF或第2页确证无效内容流；定位失效页。
- **AC-R61-U（边界/未判定）：**渲染超时但未证实文件损坏；未完成部分保持未判定。

### R-6.2 · 书签路径相对化

| 属性 | 规格 |
|---|---|
| 现行规则/严重程度 | 6.2 / 错误；来源[S03] |
| 材料定位 | 旧号4.10；物理页13、29；映射性质`FUNCTIONAL_CROSSWALK` [S04] |
| 规范要点 | 适用文件的跨文件书签不应使用绝对路径。 |
| 适用性代码 | `REF` |
| 检查 | 解析书签动作文件规格（含Unicode文件名）、路径类型及已授权目标；本地页内跳转无文件路径时不得误报。 |
| 自动处理 | 只有明确且唯一的输入到输出路径映射才改相对路径；保留合法../兄弟目录引用。 |
| 异常及不足 | 同名不同目录、盘符不明、目标未提供进入映射待办；绝不扫描全盘寻找。 |
| 不得误改 | 仅改所选文件规格；目标页、缩放、书签标题和层级不变。 |
| 操作/阶段 | `OP-BOOKMARK_PATH` / M2；检查和修改完成状态分别记录 |

- **AC-R62-P（正例）：**GoToR指向已提供兄弟目录PDF的相对路径。
- **AC-R62-N（反例）：**书签含C盘绝对路径且存在已确认映射。
- **AC-R62-U（边界/未判定）：**目标在未授权根目录；不读取且不凭同名映射。

### R-6.3 · 书签外部地址

| 属性 | 规格 |
|---|---|
| 现行规则/严重程度 | 6.3 / 错误；来源[S03] |
| 材料定位 | 旧号4.11；物理页13、29；映射性质`FUNCTIONAL_CROSSWALK` [S04] |
| 规范要点 | 适用文件书签中的网页、邮箱等外部地址受限制。 |
| 适用性代码 | `REF` |
| 检查 | 枚举URI及外部文件动作，保留实际类型和证据；普通书签标题包含网址不等于有外部动作。 |
| 自动处理 | 批次显式启用删除/重定向策略后处理。没有有效替代目标的父节点不得仅清空动作留下失效书签。 |
| 异常及不足 | 带子节点的外链书签默认需选择重定向、提升子节点或明确删除子树；未选策略则跳过该操作。 |
| 不得误改 | 未经批准的子树、页面正文和其他书签不变；删除行为属于导航变化而非纯属性保全。 |
| 操作/阶段 | `OP-BOOKMARK_EXTERNAL` / M2；检查和修改完成状态分别记录 |

- **AC-R63-P（正例）：**页内书签标题含网址但目标为本地页。
- **AC-R63-N（反例）：**适用报告中书签URI指向https网页。
- **AC-R63-U（边界/未判定）：**带有效子节点的URI父书签未给处置策略。

### R-6.4 · 书签动作类型

| 属性 | 规格 |

## 8. 输出和完成标准

交付目录有`pdf/`（已验证改写与可读原样副本）、`unprocessed/`（因打开/安全问题不能作为已核验PDF交付的原字节副本）、`reports/`（清单/结果/证据）。文件本名不加统一“修复后”后缀，不自动重命名。工作暂存、OCR中间文件、凭据和提取附件不进入`pdf/`。

批次总终态只能反映执行是否结束。文件级检查五态、操作执行结果、剩余问题和最终目标可用性共同决定“可交付程度”；不使用一个绿色圆点替代全部事实。参考文献豁免可原样通过本地适用性评估，但不能跳过可读性/密码及输入保护。

所有“已实现”必须至少有可运行代码、原生正反例、UI入口（用户功能）、输出副本与复验记录。只有规格、模拟输出、stub测试或函数返回0不构成完成。既有线性化和阅读能力复用，但本规格新增管线与组合能力须重新验收。
